# 开发学习流程

- 英文原文：Workflow.md

开发与学习是两个结果。默认完成交付并简短解释。用户要求讲清理由时提供解释，不自动安排测验或强制练习。

## 选择深度

- 解释：结合实际改动说明相关决定和取舍。
- 引导实践：用户需要时，选最多两个概念，给一个预测问题和一个安全的亲手练习，比较观察结果，再进行有范围的复述。
- 深入课程：仅在对用户所选主题有帮助时补前置知识或迁移练习。

不因旧 TASK 含学习字段就启动课程。利用已知经验，不重复用户已完成基础，不要求先重新证明学习结果才继续开发。学习问题一次一个，不代做用户练习。

## 证据

用户自述学习完成，记录为用户自述。Agent 解释可记 Introduced；用户实践支持 Practiced；成功复述并有可观察迁移证据支持 Demonstrated。除非用户明确把掌握程度设为验收条件，否则缺少学习证据不阻塞功能交付。

实现／检查证据保存在 TASK；实际发生教学时才增加学习证据。不在所有文档重复记录进度，不为常规修补更新课程表。

例子：改一个 Data Asset 引用并观察模型；解释存档为何保存 ID；比较有界子任务提示与完整历史提示。使用现有项目内容，不为课程扩大功能范围。
