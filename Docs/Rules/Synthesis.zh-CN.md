# 卡牌合成规则

## 原料流转（2026-09-09 用户确认）

一次合成尝试结算后，参与的 A、B 无论成功失败都进入弃牌堆。失败没有奖励，已付心流不退还。校验拒绝不算合成尝试，不消耗卡牌或资源。每天进入晌午时，A 的倾向向每张附着 B 的场域累加一次；查看预览或重新打开页面不触发累加。

成功的 C 直接出现在参与 A／B 当前所在节点，包括它们此前移动到的目的地。弃置原料前必须保存该稳定 NodeId。C 不进入手牌，也不需要第二次部署操作或费用。这是用户对首版 HTML 实现的纠正；初始或其他来源取得的手牌 C 保持独立的手牌部署流程。

正式数值仍须确认。用户仅授权 HTML 规则原型使用可修改的临时数值，这些数值不成为 UE 正式默认配置。

- 英文原文（Agent 阅读）：`Docs/Rules/Synthesis.md`

本文档是合成规则契约。数值系数保持为可配置数据，不得在代码中擅自创造。

## 结算顺序

1. 验证两张输入卡的 ID 和类别。
2. 合并输入卡的标签/向量表示。
3. 对候选 C 卡评分。
4. 使用 Softmax 得到候选选择概率。
5. 使用带种子的随机流选择一张候选 C。
6. 根据共鸣距离、相性、全局熵和信仰计算成功率。
7. 结算成功或失败。
8. 失败时不发放奖励。如果保留西格玛骰子，只能结算另行定义的失败侧后果。

西格玛骰子不能把失败变成奖励、部分成功或隐藏的成功路径。若仍保留其他非奖励用途，必须在数据和本文档中明确规定。

## API 契约

预览和执行必须调用同一个服务，并返回相同的计算字段。结果应包括：

- 选中的候选卡
- 候选概率
- 成功率
- 调试版本中的随机投掷或投掷 ID
- 成功/失败
- 失败后果（如果配置了非奖励后果）
- 种子或随机流位置

## 测试用例

- 无效输入
- 没有候选
- 一个候选
- 多个候选
- 零熵和最大熵
- 信仰边界
- 每一种受体类型
- 成功
- 失败且没有奖励
- 配置的失败后果（如果仍保留西格玛骰子）
- 相同种子产生相同结果
