# 架构文档 Agent 约定

- 英文原文（Agent 阅读）：`AGENTS.md`

## 目的

本目录定义如何把游戏设计转化为可维护的 Unreal 实现。这里是模块边界、运行时所有权、数据契约、持久化和集成方式的技术规范源。它不能悄悄改写由 `Docs/Rules/` 所有的玩法规则，不能违背 `Docs/Design/EN/` 中已验收的基线，也不能自行补全明确未决定的内容。

## 文档所有权

| 文档区域 | 主要负责人 | 必须参与 Review 的角色 |
|---|---|---|
| `ProgramArchitecture.md` | 主程 / 架构师 Agent | Review 程序、受影响的模块 Agent |
| `DataDrivenArchitecture.md` | 主程 / 架构师 Agent | 系统、数值和受影响的模块 Agent |
| `ModuleMap.md`、`RuntimeFlow.md`、`SaveSchema.md`、`DesignPatterns.md` | 架构师 Agent | Review 程序 |
| `Modules/<Module>/README.md` | 对应模块 Agent | 涉及边界或契约变化时由架构师 Review |
| `Docs/Decisions/` | ADR 中指定的决策负责人 | 架构师和受影响的策划负责人 |

模块 Agent 维护自己的模块文档，不能直接重写总体架构基线或其他模块的契约。

## 必须的阅读顺序

修改架构文档或模块代码前，按需要阅读：

1. `../00_INDEX.md`
2. `../ProjectState.md`
3. `ProgramArchitecture.md`
4. 涉及数据或资源时阅读 `DataDrivenArchitecture.md`
5. 按需阅读 `ModuleMap.md`、`RuntimeFlow.md`、`SaveSchema.md`
6. 目标模块的 `Modules/<Module>/README.md`
7. 相关的英文策划案和规则文档

## 边界规则

- 策划案定义意图、规则含义、约束和验收标准。
- 架构文档定义数据表示、运行时所有权、依赖和扩展接口。
- 模块文档定义实现职责、公开契约、测试和学习证据。
- 静态定义必须与可变的本局运行状态分离。
- 命令进入规则/应用层；表现层不能直接修改权威状态。
- 跨模块通信使用稳定契约、命令、结果或事件，不直接穿透访问具体对象。
- 结构性变化必须在实现前或同一次修改中添加 ADR。
- 只有边界稳定或拥有独立构建/测试需求时才创建 UE 模块。不能因为有文档目录就创建空的运行时模块。

## 修改流程

1. 确认负责的文档和模块。
2. 说明变化属于规则、数据契约、依赖关系还是实现细节。
3. 只有项目级契约变化时才修改总体架构文档。
4. 更新受影响的模块文档和测试。
5. 结构性决策新增或更新 ADR。
6. 在同一个任务中同步更新英文文档和中文镜像。
7. 运行 `Scripts/AuditDocs.ps1` 以及最小相关项目/测试验证。

## 模块文档最低要求

每份模块文档必须说明：

- 目的和当前实现状态。
- 负责人 Agent 以及允许修改的 Source/Content 路径。
- 负责事项和明确不负责事项。
- 对外数据、命令、结果和事件契约。
- 依赖关系和禁止依赖。
- 静态数据资产与运行时状态的所有权。
- 测试、调试、存档和未来网络预期。
- 学习目标和已知风险。

英文文件是 Agent 推理的规范源，中文文件是同步的用户阅读镜像。
