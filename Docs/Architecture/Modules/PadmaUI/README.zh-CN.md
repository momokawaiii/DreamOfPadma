## 1. 目的

PadmaUI 展示权威结果，并把本地输入转换为共享命令。它支持战略/RTS 风格沙盘、回合制遭遇战控制和 RealTimeAction 输入路线，但不拥有规则状态。

## 2. 负责事项

- 沙盘战略、遭遇战回合、RealTimeAction、鼠标、键盘、手柄、ACT 和 FPS 表现的输入适配器。
- 遭遇战回合控制和结束回合反馈。
- ACT RealTimeAction MVP 的 `Tab` 交互：点击 `Tab` 打开卡牌仓库面板、使背景虚化、划出五张卡，并将世界时间减缓到 1/10。
- ACT MVP 卡牌仓库/子弹时间状态激活期间，禁止移动和攻击输入；只接受基础非 A 卡相关输入，同时战斗场景保持惯性。
- 共享卡牌仓库交互：`Tab` 唤起仓库，每页显示 1—5 卡槽，鼠标滚轮请求下一页。总页数和页面边界行为暂时留空。
- 命令构建，以及不替代规则的本地输入校验。
- HUD、手牌、合成预览、地图、资源、威胁和结局界面。
- ViewModel 或只读表现状态。
- 在调试版显示计算追踪、命令失败、战斗日志和结算原因。
- 卡牌原画、图标、动画、VFX、音频、镜头和本地化的表现引用。
- ABC 卡主动技能在战斗外发动的控制界面。
- 需要时加入无障碍和输入反馈要求。

## 3. 不负责事项

PadmaUI 不负责：

- 资源、卡牌、世界、战斗或结局的权威状态。
- 合成、伤害、AI 或胜负公式。
- 直接修改 GameState、WorldState 或存档数据。
- 把玩法真相保存在 Widget 中。

UI 发送命令并显示结果/事件。按钮不可用不能替代规则验证。

## 4. 对外契约

- 输入适配器到命令的映射。
- 只读状态 ViewModel。
- 预览请求/结果视图。
- 命令成功/失败展示。
- 战斗模式、行动条、回合状态、子弹时间、分页和数字卡槽输入反馈。
- 从沙盘发起 ABC 卡主动技能的请求。
- 战斗日志和 AI 追踪展示。
- 结算以及存档/读档通知。
- 控制模式切换表现请求。

UI 契约不应把具体 Actor 所有权作为唯一表现状态方式。

## 5. 数据与运行时所有权

UI 消费表现配置、本地化 ID、图标/网格引用以及 Core/World/Gameplay 的只读视图。它拥有临时视图状态、选择、焦点和输入适配器状态。

表现数据可以变化而不改变规则定义。规则资产不能依赖 Widget 路径。

## 6. 依赖与集成

PadmaUI 依赖公开的命令、结果、事件和只读视图契约。PadmaGame 负责把 UI 与运行时服务组合。PadmaCore 不能依赖 UI。

## 7. 测试与调试证据

必须测试：

- 输入映射到正确命令。
- 非法命令显示来自规则层的解释。
- 预览显示与执行相同的计算字段。
- UI 响应世界、战斗、资源和结算事件。
- 读档后根据状态重建视图，而不是依赖 Widget 历史。
- 手柄和键盘适配器保持命令语义一致。
- 基础非 A 卡不能从沙盘提交，也不能在玩家符合条件的遭遇战行动回合之外提交，并且能显示每回合一张限制。
- 点击 `Tab` 打开共享卡牌仓库、使背景虚化、划出五张卡并进入 1/10 世界时间的 ACT 子弹时间；Encounter 手牌和 ACT RealTimeAction 分页中的 1—5 卡槽一一对应，鼠标滚轮请求下一页。
- 该状态激活期间禁止移动和攻击输入，只接受基础非 A 卡操作并保持场景惯性，快速按数字键能映射到目标 ACT 卡槽请求。总页数和页面边界行为不作假设。
- ABC 卡主动技能可以从沙盘提交而不进入战斗，并显示其配置的限制。

人工证据应包括合成预览、失败解释、节点变化、战斗日志和结算原因的截图或短视频。

## 8. 实现阶段

1. 实现最小命令面板和状态文本视图。
2. 加入手牌、ABC 主动技能控制和合成预览。
3. 加入地图/节点和资源视图。
4. 加入回合制遭遇战控制和战斗日志。
5. 遭遇战路径稳定后，加入完整 ACT RealTimeAction 子弹时间、五卡槽分页和数字卡槽战斗闭环。
6. 加入替代模式表现和打磨。

## 9. 学习目标与风险

学习目标：UMG、MVVM 或 ViewModel 设计、输入抽象、UI 反馈、本地化、无障碍和表现性能。

主要风险：因为原型方便，就把玩法规则写进 Blueprint Widget。
