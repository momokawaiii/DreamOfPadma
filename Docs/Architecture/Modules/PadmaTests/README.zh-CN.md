## 1. 目的

PadmaTests 验证规则、数据契约、运行时集成、存档迁移、确定性复现和项目冒烟行为。测试必须使用与生产路径相同的命令、规则服务和数据定义。

## 2. 负责事项

- 纯计算单元测试。
- 数据/模式和校验夹具。
- 命令与事件集成测试。
- 合成预览/执行一致性测试。
- 战斗、AI、世界变化和结算测试。
- 存档/读档和迁移夹具。
- 确定性种子/回放测试。
- PIE 和 Development 包冒烟测试。
- 有基线后进行性能和回归测量。
- 把测试证据链接到任务文件和 ProjectState。

## 3. 不负责事项

PadmaTests 不能：

- 引入会和运行时漂移的第二套伪规则实现。
- 在测试中修改生产资产。
- 在命令级测试足够时依赖 UI 点击。
- 把空测试队列通过当成玩法正确的证明。

只有存在视觉验收标准时才加入视觉测试。

## 4. 对外契约

- 测试夹具配置和稳定种子。
- Given/when/then 命令辅助。
- 状态快照和事件断言辅助。
- 数据校验报告断言。
- 存档夹具版本和迁移断言。
- 包含种子、定义 ID、命令和预期结果的复现包。

## 5. 数据与运行时所有权

PadmaTests 拥有夹具和仅测试配置，消费生产定义和服务。测试资产必须明确标记，不能悄悄进入发布内容池。

## 6. 依赖与集成

测试可以依赖所有运行时模块的公开契约，但生产模块不能依赖 PadmaTests。测试应优先使用 Core 服务和命令路径，而不是访问私有实现。

## 7. 初始测试矩阵

- 项目可以启动，编辑器目标可以编译。
- 日历边界和资源记账。
- 卡牌候选选择和成功/失败。
- 合成失败不产生奖励；如果保留西格玛路径，只产生明确的非奖励失败后果。
- 世界节点移动、占领、变化和条件路线。
- 战斗伤害、状态、统治者响应和战争天平。
- 基础非 A 卡在战斗外、玩家符合条件的遭遇战行动回合、每回合一张限制和不合法窗口的合法性。
- ABC 卡主动技能可以从沙盘发动而不进入战斗。
- ACT RealTimeAction `Tab` 卡牌仓库切换、背景虚化、1/10 世界时间减缓、禁止移动/攻击输入、子弹时间只接受卡牌输入、场景惯性、每页五个可见卡槽分页和完整战斗闭环命令映射。
- 遭遇战高层行动条条件、优先级、反应、打断、额外行动和非回合窗口；精确优先级测试等行动条规则确认后再加入。
- 已确定的两个 MVP 胜利条件和至少一种失败条件，以及未来结局定义的通用结算。
- 存档/读档往返、失败/退出时完整战前快照恢复，以及胜利提交。
- 相同种子产生相同结果。

## 8. 实现阶段

1. 在内容增长前加入 Core 计算夹具。
2. 为第一条沙盘和合成流程加入命令路径自动化。
3. 加入遭遇战行动条、卡牌发动、AI、结算和存档测试。
4. 加入完整 ACT RealTimeAction 输入/卡槽/战斗闭环测试。
5. 加入 PIE/打包冒烟测试。
6. 项目变大后加入性能基线和回归门禁。

## 9. 学习目标与风险

学习目标：Unreal Automation Framework、测试设计、确定性模拟、序列化迁移、性能证据和 CI 思维。

主要风险：测试断言了实现细节，而不是玩家可见规则和稳定契约。
