## 1. 目的

PadmaEditor 包含仅编辑器使用的工具，使数据驱动内容能够安全制作、检查、校验和预览。它必须改善内容管线，不能成为运行时依赖。

## 2. 负责事项

- Data Asset 和 DataTable 校验。
- 稳定 ID、引用、标签、曲线和概率检查。
- 卡牌发动场景、遭遇战行动条/先攻/优先级/窗口规则、ACT RealTimeAction 输入配置、每页五个可见卡槽和数字卡槽检查。精确遭遇战规则、生命周期概率和总页数暂时延期。
- 卡牌、合成、结算、世界、遭遇、AI 和剧情预览工具。
- 项目选择 CSV、JSON 或混合管线后的导入/导出适配器。
- 内容审计报告以及重复/无意义名称警告。
- 仅编辑器 GM 辅助和计算追踪视图。
- 资产创建模板和命名约束。
- 在有帮助时向内容作者展示文档/模式链接。

## 3. 不负责事项

PadmaEditor 不负责：

- 打包运行时规则。
- 运行时存档或网络行为。
- 另一套合成或战斗公式实现。
- 绕开规范数据契约的内容。

编辑器预览必须调用与运行时相同的纯计算服务。

## 4. 对外契约

- 包含资产 ID、字段、严重级别和原因的校验报告。
- 导入/导出结果和源版本。
- 卡牌、合成、结算、世界和遭遇的预览请求/结果。
- 基础非 A 卡战斗外拒绝、遭遇战行动条窗口、ACT RealTimeAction `Tab`/背景虚化/1/10 的只接受卡牌子弹时间和 ABC 卡战斗外主动技能的预览请求。
- 内容审计报告。
- 尽可能调用正常命令路径的编辑器命令封装。

## 5. 数据与运行时所有权

PadmaEditor 拥有制作时工具状态和报告。它读取并校验 Core、Gameplay、World 和 UI 内容管线拥有的定义，但不拥有最终运行时状态。

生成输出、中间文件和本地编辑器缓存不属于受版本控制的内容契约。

## 6. 依赖与集成

PadmaEditor 可以依赖运行时数据契约和编辑器 API。运行时模块不能依赖 PadmaEditor。所有校验器必须使用与运行时相同的模式版本和稳定 ID 规则。

## 7. 测试与调试证据

必须测试：

- 重复和缺失 ID 检测。
- 断裂引用和无效标签检测。
- 概率、曲线、阈值和成本范围检查。
- 基础非 A 卡战斗限定场景、玩家行动回合/每回合一张门、遭遇战行动条窗口、ABC 战斗外场景和 ACT RealTimeAction `Tab`/背景虚化/1/10 的每页五个可见卡槽分页映射。校验器不能假设总页数或生命周期概率。
- 世界图和时代/Chapter 层级检查。
- 预览与运行时一致性。
- 存在导入管线时的导入/导出往返。

报告应作为评审证据保存，但不能把绝对本地路径写进内容。

## 8. 实现阶段

1. 以 PowerShell 审计脚本作为初始静态层。
2. 第一份数据模式确定后，加入包含卡牌发动场景的小型编辑器校验器。
3. 纯计算服务建立后，再加入预览工具。
4. ACT RealTimeAction 模式配置定义后，加入 `Tab`/背景虚化/1/10 输入配置、分页/卡槽校验器；总页数和生命周期概率保持可配置。
5. 源格式确定后，再加入导入管线。

## 9. 学习目标与风险

学习目标：Unreal 编辑器扩展、资产工具、反射、数据校验、导入管线和内容制作体验。

主要风险：编辑器的便利操作产生运行时无法校验或加载的数据。
