## 1. 目的

PadmaGameplay 实现局部战斗家族。遭遇战是带条件行动条的回合制战斗；RealTimeAction 是实时路线，MVP 首先采用 ACT，FPS/其他模式作为扩展。该模块把 Core 命令和数据定义转化为战斗、能力、状态、目标、遭遇和统治者策略行为。

## 2. 负责事项

- 战斗命令验证、遭遇战行动条构建、先攻/优先级调度、当前行动编排、反应、打断、额外行动和非回合窗口。
- ACT RealTimeAction 战斗状态、ACT MVP 的 `Tab` 仓库切换、背景虚化、1/10 世界时间、禁止移动/攻击输入、保持场景惯性的处理和每页五个可见卡槽分发。总页数暂时延期。
- 普通攻击、真实伤害、防御、状态、死亡和目标结算阶段。
- C 角色、设施、核心和面向战斗的运行时状态。
- 独立 Encounter／ACT 技能／效果定义、发动策略、时钟和原生 GAS 执行；只复用获准且不夹带模式规则的基础设施／计算。
- F/D/R 属性关系和时代修正。
- 确定性的统治者巡逻、侦测、增援、反攻和威胁策略。
- 战斗日志、决策追踪和与表现无关的结果。
- 将成功 C 结果部署到合法遭遇状态，并应用明确配置且不属于奖励的失败侧后果。

## 3. 不负责事项

PadmaGameplay 不负责：

- 世界图布局、节点坐标或持久节点归属。
- UI Widget、输入设备、动画图或 Niagara 系统。
- 由 Core 所有的卡牌目录或合成公式含义。
- 实时 Actor 的存档序列化。

Gameplay 可以通过命令/事件请求 World 操作，也可以消费只读世界查询。

## 4. 对外契约

- 遭遇开始、行动条、当前行动、优先级、反应、打断、额外行动、结束回合、结果、完成和撤退契约。行动条的精确优先级在确认前保持未实现。
- ACT RealTimeAction 进入/退出、`Tab` 仓库/子弹时间输入、背景虚化、禁止移动/攻击输入、分页/卡槽选择和卡牌请求/结果契约。
- 伤害与状态计算输入/结果。
- 能力使用和目标验证结果。
- 统治者候选决策、最终动作和决策事件。
- 通过权威状态服务路由的威胁和战争天平事件提案。
- 使用稳定实体 ID 的战斗日志项。

运行时命令路径必须支持玩家输入、GM 命令、自动化、回放验证和未来网络消息。

## 5. 数据与运行时所有权

Gameplay 消费 CardDefinition、AbilityDefinition、CombatProfile、EncounterDefinition、RulerPolicy、SigmaFailureTable 和相关时代配置。它拥有遭遇运行时状态，不拥有不可变卡牌目录。

所有可调的伤害、状态、AI 和威胁值都应放在有类型的数据中。代码负责选择计算器并执行约束。

## 6. 依赖与集成

Gameplay 依赖 PadmaCore 契约。它通过合法的命令/查询/事件契约与 PadmaWorld 通信，并由 PadmaGame 组合。

任何玩法规则不能依赖 Widget 事件、关卡名称、Actor 指针身份或隐藏的帧时序副作用。

## 7. 测试与调试证据

必须测试：

- 普通攻击对防御和真实伤害。
- 至少一种 F/D/R 克制和弱匹配。
- 状态施加、叠层、消耗和死亡。
- 一次合法和一次失败目标选择。
- 基础非 A 卡在战斗外、玩家符合条件的遭遇战行动回合、每回合一张限制和不合法行动窗口的合法性。
- ABC 卡主动技能可以从沙盘发动而不进入战斗。
- ACT RealTimeAction 1/10 世界时间减缓、`Tab` 仓库切换、背景虚化、禁止移动/攻击输入、子弹时间只接受卡牌输入、场景惯性、每页五个可见卡槽和完整战斗闭环分发。
- 在精确行动条规则确认后，测试遭遇战场地/卡牌条件对先攻、反应、打断和额外行动的改变。
- 一次巡逻、侦测、增援和反攻。
- 威胁阈值和战争天平事件变化。
- 相同种子可复现战斗和 AI 决策。
- 失败或退出后，完整战前快照可以恢复所有被战斗修改的本局状态；胜利时提交结果。

调试输出应显示输入实体、数据 ID、伤害阶段、状态层、AI 候选、最终动作、随机流位置和发出的事件。

## 8. 实现阶段

1. 实现纯伤害/结果服务和测试夹具。
2. 加入遭遇战回合状态，并使用占位实体加入一次遭遇。
3. 加入统治者策略和一次反攻。
4. 加入示例遭遇所需的最小状态子集。
5. 只有遭遇战行动条路径稳定且有边界的 ACT 任务获批后，才按照 `ACTDevelopmentContract.zh-CN.md` 与 `Tab`/背景虚化/1/10 输入契约加入完整 ACT RealTimeAction 路线。
6. TASK-013 按 ADR-0004 在双模式可玩 GAS 实现前提供获准原生 GAS 依赖／生命周期基础；外部插件仍需独立 ADR。

## 9. 学习目标与风险

学习目标：Gameplay Framework 边界、战斗服务、状态效果、目标选择、GAS 准备、AI 效用策略、动画时机契约和确定性调试。

主要风险：把战斗规则埋在 Character、Ability Blueprint 或动画代码中，导致无法独立回放和测试。

## 10. 完整 MVP 模式归属

[ADR-0004](../../../Decisions/ADR-0004-Separate-Encounter-and-ACT-GAS.zh-CN.md) 将获准共享计算归于 TASK-015，将 Encounter 时间线／目录／技能归于 TASK-016／017，将 ACT 目录／序列／技能归于 TASK-030，将其卡库窗口归于 TASK-031。模式定义与运行状态保持区分。TASK-035 拥有 ACT 角色可用性／装备；回合制卡系统不是其集合。

新增必测项：拒绝错误模式绑定；配表／时钟／输入隔离；直接命令拒绝受限特性；退出后无失效效果／Task／回调；完整参与者恢复，包含获准本局阵容／武器状态。基础卡服务由装配层注入；任一模式都不重复实现共享卡生命周期，也不假定效果数据相等。
