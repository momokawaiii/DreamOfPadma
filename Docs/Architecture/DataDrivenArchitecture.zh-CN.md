## 1. 目的

本文档定义哪些内容必须数据驱动、使用哪类 Unreal 资产承载、如何进入运行时，以及哪个模块拥有结果。它是技术映射文档；策划案仍然负责游戏规则的含义、约束和验收标准。

项目应使用多个小型、类型明确的数据域，而不是一张万能大表。一份总目录可以描述全部数据域，但 Unreal 资产仍应按所有权和生命周期分开。

## 2. 数据分层

### 2.1 策划语义

策划案和规则文档定义：

- 字段的含义。
- 有效值和约束。
- 生效时机和阶段。
- 输入和输出。
- 对玩家的影响。
- 示例和验收案例。

它们不需要使用某个具体 C++ 类或资产路径来解释规则。

### 2.2 编辑定义

编辑定义是不可变的内容数据。它们使用稳定 ID，可以通过 ID 或有类型的资产引用关联其他定义。例如卡牌定义、时代配置、节点定义、遭遇定义和剧情事件。

### 2.3 运行时状态

运行时状态是当前本局，而不是资产的副本。它包括当前资源、节点归属、卡牌位置、冷却、活动变更、遭遇生命、旗标和随机流位置。运行时状态只能通过命令和规则修改。

### 2.4 事件与持久化

事件解释一次状态变化，可以被 UI、AI、剧情、音频、遥测、回放和存档历史消费。存档保存带版本的状态和稳定 ID，不保存实时对象指针。

## 4. 资产类型选择规则

### 使用 Primary Data Asset 的情况

- 对象拥有稳定身份，并被多个系统引用。
- 对象包含嵌套引用或完整内容包。
- 对象需要由 Asset Manager 加载和发现。
- 对象代表卡牌、时代、遭遇、剧情事件、统治者策略或世界配置。

### 使用 DataTable 的情况

- 行具有统一的扁平模式。
- 策划需要像表格一样比较内容。
- 数据是阈值、成本、修正、奖励或结算条件集合。
- 稳定行名可以作为内容 ID。

### 使用 CurveTable 或曲线的情况

- 规则是可调的连续关系。
- 平衡需要插值或可视化曲线。
- 曲线具有明确的输入域和输出单位。

### 使用 Gameplay Tag 的情况

- 值是类别、标签、事件主题、阵营、状态或权限。
- 多个模块需要查询同一套分类。
- 标签在本地化和资源重命名后仍应保持稳定。

不能用包含 C++ 或 Blueprint 表达式的字符串替代有类型的规则。数据行只能选择已知的计算器，不能执行任意代码。

## 5. 稳定身份和引用

每个定义都必须拥有独立于以下内容的稳定 ID：

- 显示名称。
- 本地化文本。
- 资产路径。
- Actor 类。
- 地图坐标。
- 视觉网格或图标。

建议的 ID 族：

| ID 族 | 示例形式 |
|---|---|
| 卡牌 | Card.A.Root.Mark 或 Card.C.Creator.Yog |
| 节点 | Node.Player.Home 或 Node.Ruler.Core |
| 遭遇 | Encounter.Frontier.Counterattack |
| 剧情事件 | Story.Anecdote.FirstChoice |
| 结算 | Outcome.Win.RulerCoreDestroyed |
| 数据配置 | Profile.Synthesis.MVP |

具体命名词汇由 Content/Naming.md 负责。存档或回放发布后，ID 不能回收给其他内容。

## 6. 运行时转换

推荐的数据链路是：

    资产文件
       -> 编辑器校验
       -> 资产注册表 / Asset Manager
       -> 已加载的不可变定义
       -> 类型化运行时视图
       -> 规则服务

运行时代码不应在每个命令中反复解析原始文本或随意访问资产。应在明确的边界加载和校验定义，然后把类型化视图传给计算。

定义不能包含每局可变值。例如：

- CardDefinition 包含卡牌基础标签、成本和能力引用。
- CardRuntimeState 包含位置、正逆位、冷却、伤害和当前附着。
- WorldNodeDefinition 包含节点类型和初始规则。
- WorldNodeRuntimeState 包含归属、发现状态、变化和驻军。
- OutcomeConditionDefinition 包含条件。
- RunOutcomeState 包含该条件是否以及何时结算。

## 7. 核心数据契约

### CardDefinition

最低概念字段：

- 稳定 CardId。
- CardFamily 和 Attribute。
- 种类/身份标签与合成向量标签。
- 相性。
- 消耗、基础生命/耐久和倾向。
- 带发动场景、时机、消耗、目标和冷却的能力定义 ID。
- 正位/逆位文本 ID。
- 时代卡池标签。
- 推荐输入和失败侧效果。
- 适用时的基础非 A 战斗卡槽/分页和输入元数据：每页可见 1—5 槽、Tab 仓库和鼠标滚轮翻页。总页数以及弃牌/回牌/冷却概率暂时不在此处定义。

### AbilityDefinition 与发动策略

能力定义必须独立说明技能如何发动，不能把技能发动和卡牌的放置/合成用途混为一谈：

- 稳定的 AbilityId 和所属 CardId。
- 允许的发动场景，包括 Sandbox、EncounterPlayerTurn 或 RealTimeAction。ABC 主动技能默认允许 Sandbox，特殊限制由每个技能显式配置。
- 输入方式，包括直接发动或 RealTimeAction 数字卡槽/分页。
- 资源消耗、冷却、目标规则和效果序列。
- 是否允许战斗外发动；ABC 主动技能默认允许，除非技能声明限制。
- 模式限制或所需输入配置。

基础非 A 卡打出应表示为战斗限定的卡牌操作，不能建模成通用沙盘技能。遭遇战数据必须支持玩家符合条件的行动回合门和每回合一张限制；ACT RealTimeAction 必须支持仅在子弹时间输入和每页五卡槽。ABC 卡主动技能默认包含 Sandbox 场景；特殊限制以及额外战斗场景必须由每个技能显式配置。

### SynthesisProfile

最低概念字段：

- 候选标签筛选策略。
- 向量评分策略。
- Softmax 温度。
- 共鸣距离公式配置。
- 相性修正配置。
- 熵修正配置。
- 信仰修正配置。
- 概率限制。
- 随机流名称。
- 西格玛失败/后果表 ID（如果保留西格玛骰子流程）。

### OutcomeConditionDefinition

MVP 最低字段：

- OutcomeId。
- 结算类型：Victory 或 Defeat。
- 条件类型：例如 CoreLifeThreshold、WarBalanceThreshold 等有类型的计算器。
- 来源范围和来源 ID。
- 比较符和阈值。
- 检查时机。
- 优先级。
- 表现/结果 ID。
- 可选奖励、剧情分支和存档标记 ID。
- 启用标记或配置档归属。

当前提出的两种胜利是两行数据。结算器是执行已知条件类型的代码。

## 8. 数据校验

编辑器或命令行校验必须检查：

- ID 唯一并符合命名空间。
- 引用可以解析。
- 标签和家族有效。
- 基础非 A 卡在局部战斗场景合法，且不在 Sandbox 场景合法。
- 遭遇战基础卡条目要求玩家符合条件的行动回合门和每回合一张限制，同时允许反应/打断/额外行动规则及其最终出牌额度保持独立、未决。
- ACT RealTimeAction 卡牌条目具有仅子弹时间输入配置、每页 1—5 卡槽映射、Tab 仓库映射和鼠标滚轮翻页。ACT MVP 配置必须声明背景虚化、1/10 世界时间和禁止移动/攻击输入；总页数和页面边界行为仍未确定。
- ABC 主动技能默认暴露战斗外 Sandbox 场景；特殊限制必须显式配置，且不能存在相互矛盾的模式限制。
- 资源转换循环必须有明确设计的代价、时机和风险；校验器不接受免费循环。
- 合成失败数据不能发放奖励；保留的西格玛结果必须是非奖励失败后果。
- 消耗、上限、阈值和概率处于允许范围。
- 曲线声明输入/输出单位。
- 合成候选与候选筛选兼容。
- 结算条件具有有效来源、比较符和优先级。
- 时代与 Chapter 构成合法层级。
- 世界图边引用存在的节点。
- 剧情选择引用存在的旗标或有类型效果。
- 内容定义不依赖生成目录或绝对本地路径。

校验错误需要指出资产 ID、字段和原因。警告和阻塞错误分开记录。

## 9. 确定性计算与随机流

每个随机计算必须声明：

- 本局种子或主种子。
- 随机流名称。
- 事件或命令位置。
- 输入定义 ID 和版本。
- 调试/测试版本中的投掷值。

候选选择与成功/失败使用不同的随机步骤。预览与执行使用同一个纯计算服务，但预览不能推进真实随机流或修改状态。

计算追踪必须足以复现：

- 候选分数和 Softmax 概率。
- 选中的候选。
- 成功率。
- 成功/失败投掷。
- 西格玛结果或非奖励失败后果（如果启用该路径）。
- 状态和事件输出。

## 10. 数据与存档/网络边界

资产是版本化的内容定义，存档是版本化的运行时状态。两者都不应把实时 Actor 指针序列化为身份。

当定义变化时：

- 保留稳定 ID。
- 当结果依赖定义时记录定义或内容版本。
- 存档结构变化时加入迁移。
- 旧数据需要继续加载时加入夹具。

未来联机时：

- 服务器/权威端加载同一套定义。
- 客户端可以接收只读定义和表现引用。
- 命令携带 ID 和参数，而不是 UObject 指针。
- 结果和事件是同步语言。

## 11. MVP 资产计划

第一条数据驱动切片只需要最小集合：

1. 一份 MVP 平衡配置。
2. 两张 A 卡、两张 B 卡、两张 C 卡和一张失败侧卡牌定义。
3. 一组带每页五个可见卡槽元数据的最小基础非 A 战斗手牌，包括直接伤害和保护/恢复示例；总页数和生命周期概率暂时延期。
4. 一份合成配置，以及一张（仅在保留西格玛骰子时）不含奖励结果的西格玛失败/后果表。
5. 一份资源配置。
6. 一张带稳定节点 ID 的手工沙盘图。
7. 一份遭遇战定义和一份统治者策略。
8. 一份描述条件驱动遭遇战路线和完整 ACT RealTimeAction MVP 路线的战斗模式配置，包括 `Tab` 仓库切换、背景虚化、1/10 世界时间、禁止移动/攻击输入、子弹时间和五卡槽分页。
9. 两行胜利条件和至少一行明确失败条件。
10. 一个包含两个选择的轶闻事件。
11. 一份占位表现配置。

具体数值属于数值试玩数据。资产契约应稳定到修改数值无需修改规则服务。

## 12. 所有权与文档

策划负责人定义字段含义。架构师 Agent 定义数据契约和加载边界。模块 Agent 消费契约，并负责本模块的校验和测试。Review Agent 检查代码中没有重复规则或平衡数值。

字段变化时：

1. 含义变化时先更新英文策划/规则源文档。
2. 结构或约束变化时更新英文数据契约。
3. 在同一个任务中同步所有中文镜像。
4. 更新受影响的模块 README 和测试夹具。
5. 身份、依赖、存档、网络或导入行为变化时添加 ADR。

## 13. 数据开放决策

- 最终选择 CSV、JSON、DataTable、Primary Data Asset 还是混合导入管线。
- 卡牌和能力的资产粒度。
- 公式使用曲线、类型化配置还是两者结合。
- E/L 标签的最终分类。
- 最终概率限制和单位约定。
- 表现引用放在卡牌定义内还是单独的表现配置中。
- ABC 主动技能特殊限制的数据结构；战斗外 Sandbox 权限默认为允许。
- ABC 主动技能是否也能在遭遇战或 RealTimeAction 中发动。
- 遭遇战行动条优先级、先攻修正、反应/打断优先级、额外行动规则、非回合窗口、结束回合效果及这些窗口的精确出牌额度；该部分有意留空，等实现用到时再确认。
- ACT MVP 的 `Tab` 触发、背景虚化、禁止移动/攻击输入、1/10 世界时间、每页五个可见卡槽和 Tab 仓库映射已经确定。持续/切换行为、冷却/资源消耗、页面边界行为和总页数仍待确认。
- 基础非 A 卡弃牌/回牌/冷却的具体概率，等相关卡牌实现时再确认。
- 敌我双方如何共同限制交战路线，包括地形/卡牌限制和剧情后果。
- 是否保留西格玛骰子，以及保留时的非奖励失败后果。
- 回放和存档使用的定义版本策略。
