# ADR-0005：世界地图分层存储

- 英文源文件：ADR-0005-World-Map-Storage.md
- 文档 ID：ADR-0005
- 版本：0.3
- 状态：方向已接受；具体结构仍设门禁
- 日期：2026-09-09
- Owner：Integration Coordinator／Architect，玩法由用户批准
- 任务：TASK-011；实现归 TASK-012／024／025／028／029

## 背景

来源规则描述共享沙盘节点及条件道路。用户选定在六边形外观地图上按节点与预设连线移动、使用文明 6 式斜俯视镜头，随后明确接受静态定义、.umap 表现和 SaveGame 本局变化分离。旧 TASK-007 Actor 夹具是固定表现原型，不是正式世界模型。

## 决策

1. 带版本的章节地图定义资产拥有 MapId、稳定 NodeId／EdgeId、预设连线、节点类型／地形／事件引用及初始配置引用。首实现使用项目自有的强类型 UE Data Asset；具体字段与路径在 TASK-024 预检冻结。
2. 显式连线是拓扑事实。显示坐标或相邻六边形网格不能产生合法通行。边方向、条件和精确布局仍由数据设计，未确认细节不推定。
3. .umap 拥有地表／道具、灯光、相机／表现设置及地图定义引用。节点表现映射到 ID，不拥有当前世界权威状态。
4. 世界状态服务拥有可变发现、归属、设施、道路、驻军及实体位置。玩家输入形成强类型命令；校验和付款先于原子状态更新与事件。失败保留位置和资源。
5. 版本化 SaveGame 记录 MapId／定义版本及全部获准可变本局状态。TASK-012 建立参与者契约，TASK-024／025 提供 World 状态，TASK-028／029 协调完整战斗快照及安全持久化。不将静态拓扑或 Actor 指针重复保存为事实。
6. 恢复前检查兼容性；缺失 ID、不兼容定义或加载中断须可读地失败，不能部分应用状态。重建表现或移动镜头不改变节点身份或本局进度。
7. ACT 角色／阵容保持独立身份域。世界入战传递稳定地点／地形／上下文，不引入隐式卡转换或 Actor 持久化。

## 影响与备选方案

用户可以修改表现而保留基于节点的进度。图校验和状态测试无需加载渲染关卡，仍能在 UE 中手工编辑；未来节点编辑工具可编写定义资产。已比较“全部规则字段放地图 Actor”的方案，用户未选择它。

本 ADR 不要求 World Partition、PCG、新独立模块、最终导入格式、Agent 自选八节点布局或免费移动。具体费用／限制仍由用户确认。大世界流送保持未来表现决策。

## 验证

TASK-024 测试图 ID／边、非法移动不扣费、重建表现后状态恢复及数据校验。TASK-028／029 测试完整快照、版本不匹配和安全加载失败。测试均以显式连线为准，不受六边形外观影响。

## 局部场景扩展

TASK-037 预检冻结 NodeId → SceneDefinitionId、带类型关卡／模型软引用及局部摆放。多个节点可复用场景模板；初始摆放是静态内容，可变实体摆放仍属批准的世界状态。局部 Actor 绑定已有卡实例／EntityId 和 TASK-024 提供的带版本、按观察者过滤的世界视图，不另存一份卡牌／占用。在构造 Actor 前应用可见性；过期／错误节点加载或缺失资产保留此前权威状态。D24／D25 决定查看／移动／战斗组合与公开，只有真实开战调用 TASK-028。本节扩展已接受的存储分层，不是已完成运行行为。
