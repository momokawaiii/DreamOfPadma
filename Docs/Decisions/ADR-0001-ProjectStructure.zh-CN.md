# ADR-0001：项目结构与 Agent 治理

- 英文原文（Agent 阅读）：`Docs/Decisions/ADR-0001-ProjectStructure.md`
- 状态：Accepted
- 日期：2026-09-01

## 背景

之前的原型把规则、世界状态、UI、战斗流程和持久化集中在少量全局 Actor 中。新项目既要便于学习，又要支持内容持续增长和多个 Agent 对话协作。

## 决策

采用文档优先的仓库结构，使用 Git/LFS、根目录和嵌套 Agent 约定、独立任务文件、验证脚本、稳定 ID、版本化存档和分阶段 UE 模块边界。初始运行时边界规划为 Core、Gameplay、World、UI 和 Game 组合层；实际模块等边界稳定后再逐步引入。

## 后果

- Agent 可以依据仓库状态工作，而不依赖聊天历史。
- 不加载地图也能测试规则和数据。
- 新内容应尽量避免修改中央流程代码。
- UE 二进制资源需要所有权和迁移纪律。
- 抽象会有意延迟，直到确实证明存在变化需求。
