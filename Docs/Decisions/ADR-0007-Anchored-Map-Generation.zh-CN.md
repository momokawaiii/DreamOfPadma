- 状态：Accepted；实现 TASK-048

## 决策

用户确认的锚点定义取代此前“必须逐一经过”的建议。FixedNPC 和 MainStory 锚点在不同种子中保留身份与坐标。FixedNPC 提供固定位置的人物；MainStory 的相遇／完成记录影响后续人物相关分支。允许绕路；抵达配表指定的检查点时，按照 Seen 或 Completed 一次性记录命中／错过结果，之后不重新判定，也不增加统一胜利门槛。节点对话沿用既有晌午操作限制。

`UPadmaWorldMapAsset` 保存手工 Template、可选 GeneratedLayout、可复现的生成参数与种子。所有连线均为显式有向边。有限的种子生成器在有效既有路线走廊上增加支路，保留手工节点和锚点。校验覆盖 ID、有限坐标、DAG 可达性、玩家所有的起点、标记来源和无法满足的道路前置。检查点的不同可能分支分别考虑；校验不代表数值平衡证明，也不证明每条分支都能获胜。

检查点 DataTable 显式导入 Template。运行时只读取所选的冻结布局；修改源表不会悄悄改变正在进行的地图。导入后切回 Template，需要主动重新生成。编辑预览提供临时节点手柄，应用坐标前先校验。修改 Template 代表设计者主动调整锚点；编辑生成结果时不能移动锚点。

Core 负责值结构、生成、命令、剧情状态和回滚；Game 负责 Data Asset 加载、存档边界、输入和编辑预览桥接；World 负责六边形几何、视觉代理、模型引用和 PCG；UI 展示命令并发送意图。这些是当前模块内的目录职责，没有额外堆叠新模块或万能管理器。

UE 的 PCG 插件使用 World 适配层创建的图生成环境静态网格实例。它的随机流与地图拓扑、战斗结果分离，避让节点和道路，不决定通行、NPC 身份或剧情状态。视觉主题开放模型、材质、密度／缩放及节点模型软引用。本次不要求另做独立插件、World Partition 或对称竞技平衡。

## 对 ADR-0005 的存档修订

程序地图需要在每局保存冻结的**值布局**：MapId／版本／生成器版本／种子、节点定义、有向边及检查点。这明确取代 ADR-0005 中此前“不复制静态拓扑”的限制。它属于本局快照，不是第二份独立修改的权威。仅保存稳定 ID 和值，不保存 Actor 或已加载资产指针。读取时从存档布局重建活动内容视图，先对独立保留的配置锚点参照进行兼容校验，再改变当前状态。没有布局的旧存档使用原始配表地图，不套用当前随机图。

NPC Seen／Completed、已决检查点、归属、使用／访问记录和解锁标记属于同一快照。失败的战斗移动会全部回滚。新局重新生成不会改变旧存档的几何或分支历史。修改锚点身份／坐标或地图兼容版本可能拒绝旧存档；美术可以独立修改表现而不改拓扑。

编译、自动化、资产迁移、PCG 输出和原生画面证据见 [TASK-048](../Production/Tasks/TASK-048-Anchored-World-Maps.zh-CN.md)。交互验收由用户试玩。首章为小型手工图加可选支路，使用占位美术与临时剧情文本。完整剧情制作、地形雕刻、自由六边形邻接及对称竞技生成属于后续范围。
