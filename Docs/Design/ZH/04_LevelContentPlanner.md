## 1. 关卡目标

关卡是共享沙盘，不是互相割裂的任务选择器。它要在一张小型图结构中同时展现移动、节点归属、卡牌部署、统治者反应、敌我共同限制且可以选择表现模式的交战路线、剧情选择和世界变化。

MVP 使用手工制作、数据驱动状态的小型图。PCG、World Partition、大规模地形、天气、水面和植被属于后续扩展；但 MVP 必须保留足够的数据契约，使这些系统未来可以替换当前的手工表现。

## 2. 沙盘提案

使用约八个节点的小型有向图。以下 ID 是稳定身份提案，不是最终显示名称：

| ID | 节点作用 | 初始归属 | MVP用途 |
|---|---|---|---|
| `N_PLAYER_HOME` | 归处/核心节点 | 玩家 | 玩家核心、初始手牌和安全起点。 |
| `N_SAFEHOUSE` | 薪火/安全屋节点 | 中立 | 恢复、教程检查点和战斗前存档演示。 |
| `N_FURNACE` | 熔炉节点 | 中立 | 一次临时卡牌强化或数据变换，之后变普通节点。 |
| `N_ANECDOTE` | 轶闻节点 | 中立 | 触发一次改变威慑力、信仰或路线的剧情选择。 |
| `N_FRONTIER_WEST` | 普通节点 | 统治者 | 第一次占领和巡逻教学。 |
| `N_FRONTIER_EAST` | 带地形词缀的普通节点 | 统治者 | 备用路线、潜行或发现测试。 |
| `N_RULER_OUTPOST` | 设施/防守节点 | 统治者 | 增援和反攻测试。 |
| `N_RULER_CORE` | 归处/核心节点 | 统治者 | Boss 入口和核心胜利测试。 |

至少一条路径在满足条件前是隐藏、锁定或模糊的。条件必须是明确的数据条件，不能写死成某个关卡名称判断。

## 3. 沙盘归属与移动

玩家初始领土较少。统治者拥有更大的控制区域和更高的地图熟悉度。玩家需要规划路线、逐步占领节点、部署设施或单位，并最终抵达统治者核心。

原始资料中的移动消耗示例是：

- A 卡移动：2 算力。
- C 人物或明确配置的失败侧对象移动：4 算力。
- 工事移动：6 算力。
- 核心移动：取决于场上卡牌数量，并可能允许赊账。

B 卡会随 A 卡移动。脱离 A 的 B 卡、附着卡组移动，以及核心携带场上卡牌时的具体行为需要验收确认。

## 4. 节点操作

MVP 应提供一组小型命令：

- 把可移动卡牌或单位移动到相邻节点。
- 在节点上放置 A 卡。
- 把 B 卡附着到 A 卡，或走 B 卡直接路径。
- 在合法位置执行合成。
- 部署 C 人物或 C 工事，或应用明确配置且不属于奖励的失败侧后果。
- 在不进入战斗的情况下发动符合条件的 ABC 卡主动技能。
- 让 ABC 卡角色或单位移动到敌方停留的地点，结算敌我共同限制的交战路线，并进入选定的 Encounter、ACT 或未来其他 RealTimeAction 表现模式。
- 在完成合法的行动条遭遇战或完整 ACT RealTimeAction 战斗路线后占领中立/敌方节点。
- 建造或激活一个设施。
- 进入一次轶闻并选择两个结果之一。
- 使用一次薪火恢复操作。

每个操作都要产生可见状态变化和可写入存档历史的事件。节点坐标是布局数据，地图重新制作时仍应保持节点 ID 不变。

## 5. MVP 节点规则

### 5.1 归处/核心节点

存放核心及其持久化数值。统治者核心生命归零或战争天平达到玩家边界时，MVP 以胜利结束。结算系统也要支持未来配置的其他胜利和失败条件。

### 5.2 普通节点

支持移动、部署、归属和局部战斗路线。普通节点可以拥有能够限制交战路线或行动条的地形词缀。

### 5.3 轶闻节点

提供一个剧情或世界状态选择。一个选项应帮助玩家但改变熵、信仰或威慑力；另一个选项可以用短期资源收益换取不同的长期后果。

### 5.4 熔炉节点

允许一次受控的强化或变换操作。操作完成后，节点按原始概念退化为普通节点。

### 5.5 薪火/安全屋节点

提供恢复或安全规划边界，也是教学玩家存档/读档以及战斗前自动存档反馈的位置。

## 6. 七天时代的内容节奏提案

以下是节奏提案，不是最终剧情：

| 天数 | 内容节点 | 验证的系统 |
|---:|---|---|
| 1 | 从玩家核心出发，抵达第一个前线节点。 | 黎明资源、移动、节点归属。 |
| 2 | 将 B 卡附着到 A 卡并预览合成。 | 标签向量、候选列表、概率显示。 |
| 3 | 执行一次合成并部署产物。 | 成功/失败、C 部署、资源记账。 |
| 4 | 进入轶闻节点。 | 剧情标记、信仰/熵/威慑力变化。 |
| 5 | 使用熔炉或薪火。 | 节点专属操作和存档边界。 |
| 6 | 触发统治者巡逻响应或反攻。 | 发现、增援、进入行动条遭遇战或完整 ACT RealTimeAction。 |
| 7 | 抵达统治者前哨或核心入口并结算时代结束。 | Boss 入口、胜负、天/时代边界测试。 |

即使测试时使用开发命令加速，游戏也必须保留七天一个时代的固定结构。

## 7. 内容样例

现有卡牌示例可以组成第一组内容：

- `地痕` + `蓍` 可以展示通往 `犹格索托斯` 的推荐路径。
- `安提帕鸿门宴` + `埃及艳后` 可以展示通往 `希律的舞女` 的推荐路径。
- `佛罗伦萨的曙光` + `山樱一梦` 可以展示通往 `维特鲁威人` 的推荐路径。
- `一个归来的王` 等明确配置的失败侧后果可以证明失败会产生可见的非奖励后果；合成失败不能悄悄发放奖励。

这些只是内容身份样例。本文件不冻结它们的最终平衡、视觉表现和叙事文本。

## 8. 统治者反应与世界变化

统治者应当对地图做出响应，而不是作为静态遭遇队列等待：

1. 在附近节点巡逻。
2. 发现或无法发现玩家前进单位。
3. 增援被占领的设施。
4. 反攻防守薄弱的节点。
5. 随着天数和选择提高威慑力。

MVP 要记录的世界变化包括：节点发现、节点占领、设施激活/摧毁、道路解锁、剧情选择、交战路线/表现模式触发、遭遇完成，以及一个配置好的天气/地形标记。

## 9. 剧情范围

MVP 只有一个短轶闻，包含两个选择和一个能在地图上看见的后果。它要证明剧情选择是玩法命令和持久化状态变化，而不只是对话文字。

完整 Chapter 剧情、关系网络、多分支剧情和主题胜利评级属于后续内容，但数据模型仍应支持它们的稳定 ID。

## 10. 关卡技术范围

第一版可玩版本：

- 使用一张小地图，或一组具有明确切换边界的小关卡。
- 使用手工节点图和数据定义的节点状态。
- 使用简单占位几何和光照。
- 为未来 World Partition 和 PCG 保留明确接缝。
- 让地图状态可以序列化，不能保存 Actor 指针。
- 项目资源放在 `Content/Padma/`，外部资源放在 `Content/ThirdParty/`。

第一张地图是规则试验场，不是最终美术方向，也不是最终 Chapter 地理设计。

## 11. 关卡验收清单

- [ ] 玩家和统治者共享一张可见图结构。
- [ ] 地图包含归处、普通、轶闻、熔炉和薪火节点类型。
- [ ] 至少一条路径需要条件才能解锁。
- [ ] 玩家可以占领节点，统治者可以响应。
- [ ] 一个地形词缀会改变可见规则。
- [ ] 一次剧情选择会改变持久化世界状态。
- [ ] 节点 ID 与坐标和关卡资源独立。
- [ ] 玩家可以抵达并挑战统治者核心。
- [ ] ABC 卡角色到达敌方占据地点时，能够明显触发局部战斗路线。
- [ ] 最终战斗路线可以选择/触发行动条 Encounter 或完整 ACT RealTimeAction MVP 闭环，未来模式仍可扩展。
- [ ] 地形、双方选择或卡牌效果可以限制交战路线，并且选定路线能够体现剧情后果。
- [ ] 一个七天时代可以结束，并能测试下一个边界。
- [ ] 完整战前快照、失败/退出时精确回滚到沙盘以及胜利提交流程可见。

## 12. 开放的关卡决定

- 确切节点数量和图结构。
- 两个核心是否分别位于两个 `归处` 节点，还是采用其他核心布局。
- 沙盘和遭遇战是否使用同一个 World Partition 世界。
- 隐藏路线条件和地形词缀。
- 第一条轶闻文本和两个后果。
- 每条战斗路线/表现模式分别由哪个节点、卡牌、剧情选择或遭遇条件触发，以及敌我双方如何共同限制交战路线和其剧情后果。

## 13. 学习目标

本基线用于学习关卡设计、图结构内容建模、节点归属、世界状态变化、遭遇切换、剧情标记、存档边界、数据驱动内容、World Partition 规划、PCG 接缝和后续环境制作。
