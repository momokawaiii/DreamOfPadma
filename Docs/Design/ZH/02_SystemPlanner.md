## 1. 系统职责

本文档把高层策划基线转换为可以独立测试的系统模型。它不冻结最终数值，也不规定必须使用哪些 Unreal 类。

系统层负责身份、状态变化、资源记账、卡牌数据契约、合成结算和持久化世界事件。表现层可以展示或播放这些结果，但不能重新定义规则。

## 2. 卡牌分类

### 2.1 卡牌家族

| 家族 | 概念角色 | 属性来源 | MVP职责 |
|---|---|---|---|
| A | 根源、基底、本我；原因或基础 | F；D22d 用户确认映射 | 可以占据节点、提供基本盘、携带倾向，并接受 B 卡附着。 |
| B | 福音、介质、触媒；转化环境 | D；D22d 用户确认映射 | 提供消耗、场域、装潢、降临和突变属性。 |
| C | 终结、造物、自我；生成结果 | R；D22d 用户确认映射 | 生成工事、人物、事件或道具，并携带目标值、属性和技能。 |
| 基础非 A 手牌 | 基础战斗技能手牌 | 按卡牌显式定义 | 只能在局部战斗中打出：遭遇战每个符合条件的玩家行动回合最多一张，RealTimeAction 走 ACT 子弹时间/数字卡槽路线。 |
| 额外/衍生卡 | 明确生成的辅助物或非奖励失败侧内容 | 默认不参与向量 | 位于正常候选卡池之外，由明确效果生成；不是合成失败时自动发放的奖励。 |

原始规则是 `A_x + B_x -> C_x`。卡集旧的无属性／跨家族属性标注需按用户确认的 A→F、B→D、C→R 修订，不能据此暗设例外。B 卡也可以脱离 A 卡打出，具体后果见下文。

### 2.2 卡牌数据字段

MVP 卡牌定义应当数据驱动，并把设计身份和表现资源分开。

通用字段包括：

- `CardId`
- `CardFamily`
- `Attribute`
- `CardType`
- `SpeciesOrIdentityTags`
- `VectorTags`
- `Affinity`
- `FlowCost`
- `StabilityOrLife`
- `FlowTendency`
- `EntropyTendency`
- C 卡的 `TargetFlow` 和 `TargetEntropy`
- 带明确发动场景、时机、消耗、目标和冷却的 `Abilities`
- `UprightText` 和 `ReversedText`
- `EraPoolTags`
- `RecommendedInputs`
- `ActivationContexts`
- `ActivationInput`、`BattleSlotPage` 和可选战斗卡槽
- `FailureSideEffects`

稳定 ID 必须能够承受资源重命名、本地化变化和显示名变化。

### 2.3 卡牌发动场景

基础非 A 卡与 ABC 卡的区别是发动渠道规则，不是对 A/B/C 家族分类的替代：

- 基础非 A 手牌是战斗技能卡。只有在局部战斗处于进行中时，才能执行打出操作。
- 遭遇战中，玩家每个符合条件的行动回合最多打出一张基础非 A 卡。反应、打断、额外行动和非回合窗口属于独立时序规则；这些窗口是否额外给予卡牌使用额度，等精确遭遇战规则用到时再确认并留空。
- ACT MVP 中，点击 `Tab` 会打开卡牌仓库面板、使背景虚化、划出当前页的五张卡，并将世界时间减缓到 1/10。该状态禁止移动和攻击输入，只接受基础非 A 卡相关输入，战斗场景保持惯性，再快速按数字键打出对应卡槽的卡牌。
- 可见数字卡槽每页固定为 1—5，鼠标滚轮请求下一页非 A 卡。总页数是固定还是无限，以及到达页面边界后的行为，等卡牌 UI 用到时再确认。
- ABC 卡携带的主动技能默认允许从沙盘发动。特殊限制由每个技能单独配置；满足技能条件和消耗时，可以在局部战斗之外发动。
- 为放置、附着、合成或部署而打出 ABC 卡，与发动 ABC 卡上的技能是不同操作。

遭遇战和 RealTimeAction 使用同一个卡牌仓库交互：按下 `Tab` 唤起仓库，Encounter 手牌与 RealTimeAction 数字卡槽是一一对应的同一组基础非 A 卡映射。在 ACT MVP 中，这个操作还会触发背景虚化和 1/10 世界时间的子弹时间状态。ABC 主动技能是否也能在遭遇战或 RealTimeAction 战斗中发动，需要按技能或后续全局规则明确，程序不得自行猜测。

## 3. 属性和标签模型

主要属性关系是：

```text
D 克制 F
F 克制 R
R 克制 D
```

普通克制造成双倍伤害，弱克制造成一半伤害。朋克时代取消克制关系，次世代按照原始提案使克制关系翻倍。多个修正冲突时的优先级尚待确认。

向量标签是稀疏键值数据，例如：

```text
{"奥秘": 80, "禁忌": 20}
```

向量标签与种族/身份标签分离。种族标签可以影响战斗或内容规则，但额外卡/依赖卡默认不参与 A+B 的向量选择。

## 4. 时间与时代数据

时间是显式状态，而不是在玩法代码中使用隐式取模计算：

```text
CalendarState
  ChapterIndex
  EraIndex
  DayIndex
  Phase = Dawn | Morning | Dusk
```

时间层级固定为：

```text
一天 = 黎明 -> 上午 -> 黄昏
七天 = 一个时代
七个时代 = 一个 Chapter
```

每次阶段变化都应发出事件。日终、时代变化和 Chapter 变化是不同事件，避免其他系统自行推导隐藏状态。

七个时代的卡池修正应当是数据，而不是写死在卡牌逻辑中的分支。`F-E`、`F-L`、`R-E`、`R-L` 作为原始标签保留；`E` 和 `L` 的分类含义需要后续明确。

## 5. 资源模型

### 5.1 心流

心流用于抽牌、打牌、召唤和卡牌技能。卡牌可以获得或消耗心流，也允许通过特定效果把心流转换为算力，或把算力转换为心流。资源循环既不是一律允许，也不是一律禁止：每个循环都必须是明确设计的效果，具有真实代价、时机和风险；某些设计中运气可以补偿代价。

原始资料还提出了与上限 50% 有关的默认资源获取，以及有限赊账。它们不是最终 MVP 常量。实现必须独立表示当前值、上限、赊账额度和变化来源，使平衡调整不需要重写代码。

### 5.2 算力

算力是沙盘操作资源，用于移动、建造、节点操作和部分卡牌效果。它不是心流的另一个名字。

原始卡牌和规则中的示例值包括：

- A 卡移动：2 算力。
- C 人物或明确配置的失败侧对象移动：4 算力。
- 工事移动：6 算力。
- 核心移动：取决于场上卡牌数量，并可能允许赊账。

这些数值目前只是数值评审用的提案。

### 5.3 全局状态

MVP 状态模型区分：

- `GlobalEntropy`：全局熵
- `Faith`：信仰
- `CoreLife`：核心生命
- `WarBalance`：战争天平
- `Threat`：威慑力
- `Flow` 和 `FlowCap`：心流及上限
- `Computation` 和 `ComputationCap`：算力及上限
- 使用稳定值的卡牌的 `Stability`

每次变化都应在开发/测试版本中记录来源、原因和命令/事件 ID。

## 6. 手牌、牌堆、弃牌和卡牌状态

原始资料区分 ABC 卡和基础非 A 手牌，并指出 ABC 卡会进入弃牌堆。基础非 A 卡是战斗限定的手牌技能，而 ABC 主动技能可以在局部战斗之外发动。这个发动权限不能与牌堆位置混淆。原始资料还描述了日终回收、牌堆顶/底、焚毁/放逐、手牌上限和牌堆耗尽惩罚等规则。

MVP 数据模型必须支持：

- 抽牌堆、手牌、弃牌堆和可选的额外卡组。
- 卡牌移动到牌堆顶、牌堆底、弃牌、焚毁或放逐。
- 按卡牌规则决定返回时机。
- 手牌上限，以及无法抽牌时的明确原因。
- 使用随机种子进行可复现洗牌。

基础非 A 卡的生命周期由卡牌或效果决定。打出后可以进入弃牌、返回牌堆或进入冷却。遭遇战执行“每个符合条件的玩家行动回合最多一张”；非回合制模式没有每回合张数上限，但仍受生命周期、消耗、冷却和其他数据限制约束。弃牌、回牌和冷却的具体概率，以及卡牌总页数，暂时留空，等相关卡牌实现时再确认。上面的合法发动场景已经属于本次澄清后的契约，程序不能把它们悄悄合并成一个通用打牌路径。

## 7. A+B 合成流程

当前 MVP 理解为分层生成流程，主要结果只有成功和失败两种。

### 7.1 结算顺序

1. 验证输入卡牌 ID、家族、归属、可用状态和消耗。
2. 结算 A/B 的位置、附着关系、正置/逆置和当前场域值。
3. 把 A 和 B 的稀疏向量标签相加得到 `V`。
4. 建立候选 C 集合；通常要求候选卡与向量共享允许的标签。
5. 使用向量点积计算每张候选卡的分数。
6. 使用带温度的 Softmax 选择一张候选 C。
7. 使用共鸣距离、A 卡相性、全局熵和召唤者信仰计算成功率。
8. 使用带种子的随机流结算成功或失败。
9. 如果失败，不发放奖励。如果保留西格玛骰子，只结算另行定义的非奖励失败后果。
10. 生成足以支持预览、重放、存档和调试的结果与事件。

Softmax 决定“尝试生成哪一张候选 C”，它本身不决定选中的 C 是否成功出现。

### 7.2 B 卡附着和直接打出

B 卡附着在 A 卡后，B 卡自带场域成为 A 的心流倾向和熵倾向逐步累加的环境，直到执行合成。进入概率计算阶段会消耗配置好的算力。

B 卡脱离 A 卡直接打出时：

- 仍可以进入向量计算路径。
- A 的权重按 `1` 处理。
- 正常情况下由 B 卡传给生成 C 的突变属性不生效。

累加的具体时机，以及 B 卡是否可以作为独立场域物体留在场上，需要在实现验收中确认。

### 7.3 候选选择

对候选 `i`，当前使用的分数是：

```text
S_i = dot(V, CandidateVector_i)

Softmax_i = exp(S_i / T) / sum(exp(S_j / T))
```

`T` 是配置的温度值。候选选择的随机投掷和随机流位置必须在开发/测试版本中记录。

如果没有任何共同向量标签，原始资料提出从 C 卡中等概率随机选择的兜底路径。该路径会增加风险，并可能在生成物留场期间产生每日熵代价。其确切持续时间和移除消耗待确认。

### 7.4 成功率

当前依据原始资料的公式是：

```text
D = abs(BFinalFlow - CTargetFlow)
  + abs(BFinalEntropy - CTargetEntropy)

P_success = (100 - D
             + M_affinity
             + M_global_entropy
             + M_faith) %
```

示例中的相性修正为：

```text
万能受体    +10%
介稳受体    -10%
异形受体    -20%
```

全局熵修正描述为：

```text
M_global_entropy = -(CurrentGlobalEntropy / 10) ^ 1.5
```

当前候选信仰分段函数为：

| 信仰 x | `M_faith(x)` |
|---|---|
| 95 <= x <= 100 | `10 + 1.0 * (x - 95)` |
| 80 <= x < 95 | `4 + 0.4 * (x - 80)` |
| 40 <= x < 80 | `-4 + 0.175 * (x - 40)` |
| 20 <= x < 40 | `-15 + 0.55 * (x - 20)` |
| 0 <= x < 20 | `-33 + 0.9 * x` |

概率是否限制在 0%-100%、超出范围的熵如何处理、各修正值的单位含义，都必须在编码前确认。MVP 仍只能给出成功/失败，不得偷偷增加“部分成功”状态。

### 7.5 西格玛骰子和失败侧

当前项目澄清对本文档有效：

- 西格玛骰子不替代主要成功率公式。
- 合成失败仍然是失败，且不产生奖励。
- 如果保留西格玛骰子，它只能结算另行定义的非奖励失败后果，不能产生隐藏成功或部分成功。
- 不存在名为“部分成功”的第三种主要结果。

是否保留西格玛骰子、骰子数量、面数、阈值和非奖励失败后果表属于开放的数值策划事项。

### 7.6 预览一致性

预览和执行必须调用同一个纯结算服务。预览可以展示候选概率、成功率、失败侧结果类别、消耗和调试种子，但不能消耗卡牌、资源、随机流或世界状态。

## 8. 世界状态变化模型

每一个需要持久化的变化都应当可以表示为：

```text
命令 -> 验证 -> 状态变化 -> 事件 -> 历史/存档
```

示例包括节点占领、道路开通、设施摧毁、剧情选择、天气变化、遭遇完成和卡牌部署。坐标是布局数据，稳定节点 ID 才是身份。

## 9. MVP 建议测试卡组

以下样例用于验证模型，不代表已经冻结数值：

- A：`地痕`、`安提帕鸿门宴`
- B：`蓍`、`埃及艳后`
- C：`犹格索托斯`、`希律的舞女`、`维特鲁威人`
- 失败侧后果样例（仅在明确为非奖励时）：`一个归来的王`、`约瑟夫残影`
- 基础非 A 战斗技能：一次普通攻击、一次真实伤害、一次保护/恢复

卡牌上展示的推荐路径，例如 `地痕 + 蓍 -> 犹格索托斯`，是内容提示，不代表 Softmax 必然强制选择该结果。

## 10. 开放规则

- 心流、算力、生命、信仰、熵和战争天平的初始值与上限。
- 所有概率是否限制到 0%-100%，以及限制发生在哪一步。
- B 场域累加的具体时机和进入概率阶段的算力消耗。
- 没有共同标签时的兜底行为。
- 基础非 A 卡的生命周期，以及 ABC 主动技能是否也能在战斗中发动。
- 是否保留西格玛骰子、骰子格式和非奖励失败后果。
- 卡牌升级／生命周期时机仍待定。ADR-0004 规划两种战斗模式使用原生 GAS；这不决定完整卡牌生命周期或升级规则。
- 遭遇战行动条优先级、先攻修正、反应/打断优先级、额外行动规则、非回合窗口和结束回合效果的精确表。
- 剩余的 ACT UI 细节，例如关闭/再次进入行为和页面边界行为；MVP 的 `Tab` 触发、背景虚化、1/10 世界时间、禁止移动/攻击、每页五个可见卡槽和 Tab/卡牌仓库映射已经确定。总页数暂时留空。

## 11. 学习目标

本基线用于学习数据契约、`USTRUCT` 类规则数据、确定性随机流、纯规则服务、事件驱动状态变化、资源记账、公式测试、预览/执行一致性和版本化存档设计。

## 12. 卡集合与 ACT 装备阵容（2026-09-08）

区分三个概念：（1）回合制／ABC 卡系统，包含为 Encounter 路线部署在沙盒的角色；（2）用于战斗总设置角色／武器选择的独立 ACT 角色卡集合；（3）身份／槽位映射共享但各模式效果分别配置的基础非 A 技能卡。

TASK-020 拥有回合制／ABC 生命周期及共享基础技能卡契约。TASK-035 拥有 ACT 角色可用性和阵容／装备状态。ACT 角色卡不自动参与 ABC 合成、沙盒部署或回合制牌堆生命周期。定义 ID、持有实例和战斗实体是不同身份；模式进入不会自动转换角色卡。

ACT 地形限制明确指向角色、武器、技能或特性。具体限制行为及阵容／预设与本局持久化范围仍属 D20；限制特性不能静默禁用整个角色。所有未接受数值输入遵循 D03，由用户逐项确认。见 [ADR-0004](../../Decisions/ADR-0004-Separate-Encounter-and-ACT-GAS.zh-CN.md) 和[决策登记表](../../Production/MVPDecisionRegister.zh-CN.md)。
