## 1. 基线约定

用户已于 2026-09-02 验收本文档对可玩 MVP 的高层理解。本文档是实现基线，但不代表所有数值、卡牌、地图细节和优先级规则都已经最终确定。

标记为“待确认”“提案”或“开放问题”的内容，不得被程序直接当成最终规则实现。如果本文档与原始资料存在冲突，Agent 必须报告冲突，不得自行选择并隐藏差异。

## 2. 项目定位

《Dream of Padma》是一款用于表达完整原创世界观和系统百科的独立游戏。项目重点不是成为面向大众市场的爆款，而是把世界观、系统因果和完整制作流程做成一个可运行的作品。

MVP 需要证明项目可以连接以下内容：

1. 数据驱动的卡牌与合成系统。
2. 会因玩家操作而改变状态的共享沙盘。
3. 阶段、时代和 Chapter 组成的时间结构。
4. 面对强大统治者阵营的非对称冲突。
5. 具有规则驱动回合制遭遇战的战略沙盘层。
6. MVP 中可完整游玩的 ACT 实时战斗路线，同时为 FPS 和其他小游戏模式保留扩展空间，并保持规则结算可复现。
7. 能够继续扩展战斗模式的制作流程，而不是要求第一版同时完成所有模式。

玩家的核心体验不是单纯变强，而是进行一次有意义的操作，观察它如何改变系统和世界，再根据变化规划下一步。

## 3. MVP 成功标准

当玩家可以完成一段短小、可重复的“沙盘 - 战斗 - 返回沙盘”流程，并且理解世界为什么发生变化时，MVP 才算成功。

本基线中的 MVP 包括：

- 一个七天时代，位于结构正确的七时代 Chapter 之中。
- 一张约八个节点的小型共享沙盘。
- 一个玩家核心和一个统治者核心。
- 一套统治者巡逻策略、一次增援/反攻响应和一个 Boss 战。
- 一组小型卡牌目录：基础卡、至少两张 A 卡、两张 B 卡、两张 C 卡，以及一个不发放奖励的失败侧后果定义。
- 完整的 A+B 候选选择与成功/失败流程，包括预览一致性和随机结果复现。
- 一次节点占领、一次节点变化、一个轶闻事件和一个薪火/恢复节点。
- 可玩的战略/RTS 风格沙盘，以及一场包含条件行动条的完整遭遇战。
- 一轮从进入、出牌到结算完整可玩的 ACT RealTimeAction 战斗；FPS 和其他 RealTimeAction 模式作为后续扩展路线。
- 战斗前自动存档，以及当前流程的存档/读档闭环。

初始资源、具体卡表、地图布局和 Boss 身份仍属于实现/试玩决定，不由本基线固定。

## 4. 玩家主循环

```text
准备手牌和资源
        -> 进行战略沙盘操作
        -> 可在战斗外发动 ABC 卡主动技能
        -> 选择合法的局部战斗路线
           -> 遭遇战：根据条件行动条结算先攻、优先级、反应、打断、
              额外行动和合法的基础非 A 卡操作
        -> RealTimeAction/ACT：点击 `Tab` 使背景虚化、划出五张卡，
              进入原世界时间 1/10 的子弹时间；按下数字卡槽键并实时结算卡牌效果
        -> 结算战斗结果并返回沙盘
        -> 更新熵、信仰、威慑力和战争天平
        -> 在安全边界存档并进入下一天
```

沙盘是战略层。它采用阶段边界规则，并可以使用 RTS 风格的选择和指令表现，但沙盘本身不是实时战斗。

当玩家控制的 ABC 卡角色或单位移动到敌方停留的地点时，会在该地点创建 Encounter 局部战斗，并采用类似《阴阳师》的回合制表现。遭遇战不是固定的“玩家回合后统治者回合”轮换：先攻和行动条轮换由场地、卡牌技能等特殊条件决定，并支持优先级、反应、打断、额外行动和非回合技能窗口。高层行为已经确定，但行动条的精确公式和优先级表暂时留空，等真正实现该规则时再确认。

基础非 A 手牌仍然是战斗技能：在遭遇战中，玩家每个符合条件的行动回合最多打出一张。这个单回合一张的限制不适用于回合制以外的路线，但卡牌生命周期、消耗、冷却和其他数据限制仍然适用。卡牌生命周期的具体概率，等相关卡牌实现时再确认。

第一个 RealTimeAction 模式采用 ACT。MVP 中点击 `Tab` 会打开卡牌仓库面板、使背景虚化、划出当前页的五张卡，并进入子弹时间；世界时间减缓到正常速度的 1/10。该状态禁止移动和攻击输入，只接受基础非 A 卡相关输入；战斗场景保持惯性，不进行完全暂停。快速按下数字键会打出对应卡槽的卡牌并施加主动效果。可见数字卡槽每页固定为 1—5，鼠标滚轮请求下一页。总页数是固定还是可无限扩展，以及翻页到边界后的行为，等卡牌 UI 真正实现时再确认。

遭遇战和 ACT 使用同一个卡牌仓库交互：按下 `Tab` 唤起卡牌仓库，Encounter 手牌与 RealTimeAction 数字卡槽是一一对应的同一组基础非 A 卡映射。在 ACT MVP 中，`Tab` 同时触发背景虚化和子弹时间状态。

ABC 卡携带的主动技能是另一条发动路径。默认允许从沙盘发动，特殊限制由每个技能单独配置。因此玩家无需进入遭遇战或 RealTimeAction 战斗即可发动这些技能。ABC 主动技能是否也能在战斗中发动，仍需按技能或全局规则明确。

## 5. 时间与阶段

时间层级固定为：

```text
一天    = 黎明 -> 上午 -> 黄昏
七天    = 一个时代
七个时代 = 一个 Chapter
```

必须显式保存 `ChapterIndex`、`EraIndex`、`DayIndex` 和 `Phase`。MVP 只完整游玩一个七天时代，但应通过开发命令测试时代边界和 Chapter 边界。

原始资料中的七个时代主题保留为数据：

1. 图腾时代：强化 F-E 卡并偏向抽取对应卡池。
2. 蒙昧时代：强化 F-L 卡并偏向抽取对应卡池。
3. 启蒙时代：强化 D 卡，并且可以有更多延长时代的方式。
4. 死仇时代：强化 R-E 卡并偏向抽取对应卡池。
5. 摩登时代：强化 R-L 卡并偏向抽取对应卡池。
6. 朋克时代：取消克制关系。
7. 次世代：克制关系翻倍。

`E` 和 `L` 子标签在当前资料中没有完整定义，MVP 不得自行补充其含义。

## 6. MVP 阶段行为

| 阶段 | 基线中的玩家行为 |
|---|---|
| 黎明 | 结算每日开始效果、降临效果、抽牌/刷新手牌，并同步获得配置好的资源。 |
| 上午 | 发出沙盘移动、放置、附着、合成、建造和符合条件的 ABC 主动技能指令。满足世界条件时可在任意时间进入局部战斗；进入后由战斗自身的行动条或 ACT 循环控制。 |
| 黄昏 | 结算非即时伤害、场域与时间效果、熵和威慑力变化、弃牌/回牌规则以及每日结束检查。 |

遭遇战的先攻和行动条轮换由明确条件驱动，包括场地和卡牌技能。程序必须用类型化规则表达优先级、反应、打断、额外行动和非回合窗口；涉及随机时使用可复现的随机流。具体优先级表和行动条算法有意延期，必须留空，不能由 Agent 自行补充。

局部战斗是一个独立的模式事务。进入战斗会暂停沙盘时间，并记录所有与战斗相关的本局状态的完整版本化快照；胜利时提交战斗变化，失败或玩家退出时完整恢复战前快照，不留下部分战斗状态，再返回沙盘。

## 7. 核心系统支柱

### 7.1 卡牌

- A 卡代表根源、基底、本我。属性为 F，用户于 2026-09-08 确认 D22d；冲突卡集标注需修订。
- B 卡代表福音、介质、触媒。属性为 D，用户于 2026-09-08 确认 D22d；冲突卡集标注需修订。
- C 卡代表终结、造物、自我。属性为 R，用户于 2026-09-08 确认 D22d；冲突卡集标注需修订。
- C 卡可以是工事、人物、事件或道具。
- 基础非 A 卡是战斗技能卡，不是通用沙盘行动。它只能在局部战斗中打出：遭遇战中玩家每个符合条件的行动回合最多一张，ACT MVP 的 RealTimeAction 中走 `Tab` 子弹时间加数字卡槽输入路线。回合制以外没有每回合张数上限，但生命周期和其他消耗由数据定义，具体概率延期确认。
- ABC 卡携带的主动技能默认允许从沙盘发动，特殊限制由每个技能单独配置。这是技能发动，不等同于打出基础非 A 手牌。
- 基础非 A 手牌和额外/衍生卡组属于独立内容类别。
- 卡牌可以有正置和逆置两种状态。
- 稳定的玩法 ID 与显示名称、资源路径分离。

### 7.2 资源

- 心流主要用于抽牌、召唤和卡牌技能。
- 算力主要用于沙盘移动和世界操作。
- 全局熵既是风险，也是可以被利用的资源压力，不只是惩罚。
- 信仰影响合成，也可能成为胜负条件。
- 核心生命、稳定值、威慑力和战争天平是不同的数值。
- 资源转换循环不是一律允许，也不是一律禁止。循环必须是明确设计的效果，具有真实代价、时机和风险；某些设计中运气可以补偿代价，但循环不能免费。MVP 应让代价和随机补偿可观察，而不是从架构上禁止循环。

### 7.3 共享沙盘

玩家与统治者处于同一张地图。玩家领土较少，需要逐步占领通往统治者核心的路线。节点归属、设施、巡逻、发现、天气/地形修正和剧情选择，都可能改变后续地图状态。局部战斗的交战路线由敌我双方共同限制；场地、地点选择和卡牌技能可能限制可选距离或路线。最终确定的战斗路线可以触发 Encounter、ACT 或未来的其他 RealTimeAction 表现模式，也可以改变剧情推进。

### 7.4 冲突与胜利

原始资料定义了从 50/50 开始的战争天平。A 卡兴亡、设施建造或摧毁、核心受到重大威胁等高光事件会推动天平，而不是让天平始终匀速变化。

原始资料还描述了核心摧毁、信仰崩塌，以及神迹、人迹等主题化胜利。MVP 的两个主要胜利条件确定为：

1. 敌方核心生命归零。
2. 战争天平完全倾向我方。

信仰崩塌和神迹/人迹胜利等级作为未来兼容的结局定义保留。结算系统后续必须能够按文档规定扩展其他胜利和失败方式，而不改变 MVP 的结算器。

## 8. 表现和模式范围

战略沙盘采用 RTS 风格的选择和指令表现：选择卡牌或单位，发出移动和世界操作指令，观察共享地图，并对统治者行动做出反应。

遭遇战是带条件行动条的回合制局部战斗模式。RealTimeAction 是实时局部战斗家族，MVP 首先采用 ACT，后续可以扩展 FPS 或其他小游戏表现。架构需要提供共享的模式和卡牌发动命令，让这些路线共用规则状态，同时更换镜头、占有对象、时间表现和输入适配器。敌我共同确定的交战路线是玩法触发条件，可以选择表现模式并影响剧情推进，不能简化成单纯的镜头选择。

MVP 包含一轮完整可玩的 ACT RealTimeAction 战斗。敌我共同限制的交战路线数据模型及其剧情触发关系仍需评审；FPS 和其他模式属于后续扩展路线。

## 9. 本基线明确不包含的内容

- 完整制作一个 Chapter 的 49 天内容。
- 制作全部七个时代卡池和完整卡牌百科。
- 完成全部大阿尔卡纳/启示卡。
- 完整 GAS 卡牌生命周期和全部升级规则。
- 联机、SDK、热更新和正式平台发布。
- 完整 World Partition、PCG、天气、水面、植被和电影化制作。
- 生产级 Substrate Toon 美术方向；渲染研究应作为独立技术任务。

这些是后续扩展目标，不是永久否决的功能。
