## 1. 战斗目标

战斗是更大沙盘冲突在局部空间中的表现。它需要让卡牌构筑、站位、资源压力、熵、信仰和战争天平同时产生意义。

MVP 应先证明一场完整遭遇战和一轮完整可玩的 ACT RealTimeAction 战斗，而不是实现所有状态、所有卡牌、所有 AI 行为和所有控制模式。规则服务必须独立于动画、Niagara、镜头和 Actor 生命周期。

## 2. 战斗模式模型

游戏有一个战略沙盘层和两类局部战斗：

1. 遭遇战采用带规则驱动行动条的回合制，不是固定的“玩家后统治者”轮换。场地、卡牌技能、先攻、优先级、反应、打断、额外行动和非回合技能窗口都可能改变下一次行动者。
2. RealTimeAction 是实时局部战斗路线。MVP 首先采用 ACT，FPS 和其他小游戏模式作为扩展路线。ACT MVP 中点击 `Tab` 会打开卡牌仓库面板、使背景虚化、划出当前页的五张卡，并将世界时间减缓到 1/10。该状态禁止移动和攻击输入，只接受基础非 A 卡相关输入，战斗场景保持惯性；快速按数字键打出对应卡槽的卡牌。

沙盘不是局部战斗。它承载移动、放置、附着、合成、建造、剧情选择和由数据允许的 ABC 卡主动技能。ABC 卡主动技能默认允许从沙盘发动，不需要进入遭遇战或 RealTimeAction；特殊限制由每个技能配置。ABC 主动技能是否也能在局部战斗中发动，仍需按技能或全局规则评审。

当玩家控制的 ABC 卡角色或单位移动到敌方停留的地点时，会在该地点触发 Encounter 局部战斗，并采用类似《阴阳师》的回合制表现。最终确定的交战路线可以选择/触发 Encounter、ACT 或未来的其他 RealTimeAction 表现模式，也可以触发剧情后果。

基础非 A 卡是战斗技能卡，不是通用沙盘行动：

- 遭遇战：当前操作者必须是玩家，并且处于符合条件的玩家行动回合；每个这样的回合最多打出一张基础非 A 卡。反应、打断和额外行动窗口是否额外给予卡牌使用额度，随精确遭遇战规则留空。
- RealTimeAction：ACT 模式必须已激活，ACT MVP 的 `Tab` 卡牌仓库/子弹时间状态必须已经打开，再用数字卡槽选择卡牌。该状态禁止移动和攻击输入。每页卡槽固定为 1—5，鼠标滚轮请求下一页；总页数和页面边界行为暂时留空。
- 沙盘或任何其他非战斗场景：拒绝打出请求。

原始资料中的上午四类行动（打出 A、打出 B、打出 C、使用 C）描述的是合法的沙盘/卡牌操作，不会把遭遇战变成实时战斗，也不会取消基础非 A 卡的回合限制。底层命令和规则服务保持确定性，未来可以由玩家输入、GM 命令、测试或网络消息驱动。

## 3. 日历与局部战斗结算

| 边界 | 战略/战斗职责 |
|---|---|
| 黎明 | 结算每日开始效果、计划降临、资源获得和明确标记为每日的恢复。 |
| 上午 | 结算沙盘移动、放置、卡牌反应、合成、建造、剧情行动和符合条件的 ABC 主动技能。满足世界条件时可在任意日历阶段进入局部战斗；进入后暂停沙盘时间。 |
| 黄昏 | 结算阶段伤害、场域与时间效果、熵、威慑力、牌堆变化和日终后果。 |

全局日历阶段不替代局部战斗时序：

- 遭遇战使用条件驱动的行动条。MVP 最低契约是战斗开始、先攻/行动条构建、当前行动结算、优先级、反应、打断、额外行动和非回合窗口、合法基础非 A 打出，以及类型化战斗结果事件。
- RealTimeAction 使用 ACT 动作／帧循环及自己的 GAS 执行和配表，负责世界时间倍率、子弹时间窗口、卡槽分发及效果结算。Encounter 拥有独立解析器；只有明确相同的规则含义才复用纯计算和强类型事件。
- 战斗通过类型化结果返回沙盘，不能绕过正常命令/事件路径直接修改世界；失败或退出恢复战前快照，胜利提交战斗结果。

当前契约不再把遭遇战和距离战理解为同一系统的两种结算时机：遭遇战是回合制，RealTimeAction 是独立的实时路线。如果保留“距离战”等原始术语，必须在实现前映射到其中一条路线。

先攻表示遭遇战第一个及后续行动的规则顺序。场地、卡牌技能和其他条件可以修正行动条。任何随机平局处理或先攻投掷都必须使用命名的带种子随机流，优先级表必须由数据驱动。

## 4. 战斗实体

第一场战斗包括：

- 一个具有生命、信仰、心流、算力和战争天平影响的玩家核心。
- 一个拥有相同基础胜负属性、但具有非对称优势的统治者核心。
- 少量作为根源或战场锚点的 A 卡。
- C 人物单位和一个 C 工事。
- 一个明确配置且不属于奖励的失败侧后果（如果样例战斗需要）。
- 一张用于直接伤害的基础非 A 战斗技能卡，以及一张保护/恢复卡。

每个实体都有稳定玩法 ID。Actor、Pawn 或 UObject 指针永远不能成为存档或事件历史中的身份。

## 5. 伤害和状态词汇

原始资料区分攻击伤害和真实伤害：

- 攻击伤害会受到防御的影响。
- 真实伤害绕过普通防御。
- “击伤”表示生命或稳定值确实被扣除。

原始状态词汇暂时保留，但若干定义在完整实现前需要精确评审：

| 状态 | 当前工作解释 |
|---|---|
| 强力 | 攻击 +1；使用后消耗相应层数。 |
| 形意 | 原始资料描述为涉及真实伤害的层数效果，同时又说形意护盾是真实护盾，前后存在冲突，需要确认。 |
| 抗衡 | 每层抵挡一次伤害。 |
| 嘲讽 | 数值越高越优先被选择，默认值为 0。 |
| 归墟 | 原始资料描述为每层抵挡一点/一次伤害，与抗衡的区别待确认。 |
| 内伤 | 可叠加的中毒类效果，每次触发造成 1 点伤害并消耗 1 层。 |
| 空门 | 每层抵挡一次异常状态施加。 |

MVP 只使用样例遭遇所需的最少状态。在用户确认前，不能擅自把“形意”和“归墟”都实现成同一种护盾。

## 6. 属性克制

```text
D 克制 F
F 克制 R
R 克制 D
```

普通情况下克制造成双倍伤害，弱克造成一半伤害。朋克时代取消关系，次世代按照原始提案使克制关系翻倍。

伤害流程应当暴露以下阶段，便于调试和数值测试：

```text
基础行动
 -> 攻击/真实伤害分类
 -> 属性关系
 -> 防御和护盾处理
 -> 状态反应
 -> 生命/稳定值变化
 -> 击伤事件
```

原始资料的默认距离是技能距离 1、普通攻击距离 0，除非卡牌另有说明。这是配置化默认值，不应把距离硬编码到每个技能里。

## 7. 战争天平和高光事件

战争天平从 50/50 开始，是玩家和统治者之间可视化的拉锯条。

天平由高光事件推动，而不是持续匀速移动。MVP 需要支持：

- A 卡被摧毁或移除。
- 设施建造或摧毁。
- 核心生命或信仰受到重大威胁。
- 道具、技能、剧情选择或胜利行为的明确影响。
- 熵灾祸的配置后果。

当指针达到玩家胜利边界时，玩家获胜。这是已经确定的两个 MVP 胜利条件之一，另一个是统治者核心生命归零。具体边界数值以及同时发生多个事件时的处理顺序，交由数值评审。结算系统仍需为文档规定的其他胜利和失败方式保留扩展能力。

## 8. 核心生命、信仰和熵

核心生命和信仰是分开的失败相关数值。信仰同时影响合成，也能被卡牌、事件和每日效果改变。

全局熵不只是惩罚。遭遇战至少要有一条低熵安全路线和一条高风险路线，后者可以换取明显优势或灾祸。灾祸必须归因于引发它的一方，并通过明确数据影响战争天平或后续状态。

MVP 不要求完整灾祸百科，但必须有一条可复现的低风险路径和一条可测试的高风险路径。

## 9. 统治者 AI

统治者是非对称阵营：初始领土更多、资源更强，并且更熟悉地图。

### 9.1 MVP 必须具备的行为

1. 使用不消耗普通巡逻算力的“执律者”巡逻配置路线。
2. 根据简单视野规则发现或无法发现玩家单位。
3. 节点被占领后对邻近设施或节点增援。
4. 在占领节点防守不足时发起反攻。
5. 防守统治者核心，并在 Boss 战中选择合法目标。
6. 按每日节奏提高威慑力，并在达到阈值时响应。

原始资料说明，玩家单位不在执律者视野内时进入潜行，并忽略统治者对 C 卡的威慑力惩罚。MVP 应提供一条可见的潜行路线和一条会触发敌方响应的路线。

### 9.2 威慑力升级

威慑力每天缓慢上升；统治者成功反攻或玩家做出有利于统治者的轶闻选择时大幅上升；玩家成功占领节点或完成明确的解放民众事件时下降。

达到峰值时，原始资料提出清零威慑力，并派出强大的天使直接降临玩家设施、强制开战。第一版可以暂不制作完整天使战，但数据模型要保留阈值和重置行为。

### 9.3 AI 决策方式

MVP AI 使用可调试的确定性优先级/效用策略，不使用 LLM 作为运行时自主 Agent。每次决策都应暴露：

- 候选行动。
- 前置条件。
- 分数或优先级理由。
- 最终行动。
- 带种子的平局处理信息。

这样既能调试 AI，也为未来接入更复杂策略保留边界。

## 10. 控制与战斗模式

战略沙盘采用 RTS 风格表现，用于选择、移动、放置、世界操作和回应统治者。这是战略层，不是遭遇战的定义。

遭遇战是带条件行动条的回合制战斗模式。RealTimeAction 是实时战斗家族；MVP 首先采用 ACT，FPS 或其他小游戏表现属于后续适配器。战斗命令契约不应知道输入来自俯视光标、第三人称角色还是第一人称武器；输入适配器和模式配置把表现输入转换为类型化命令：

- 沙盘战略指令。
- 遭遇战行动条、反应、打断、额外行动和结束回合请求。
- ACT RealTimeAction 子弹时间进入和数字卡槽打牌请求。

战斗路线的敌我共同结算数据、双方施加的限制，以及路线条件如何映射到剧情触发，仍是开放设计决定。但已经确定：路线可以选择/触发 Encounter、ACT 或未来的其他 RealTimeAction 表现模式，也可以影响剧情推进。第一种 RealTimeAction 变体已经确定为 ACT，MVP 必须完成一轮可玩的 ACT 战斗闭环。

## 11. MVP 遭遇战基线

第一场遭遇战应包含：

- 一个玩家控制的 A 卡锚点。
- 一个玩家 C 人物和一个玩家 C 工事。
- 一个统治者巡逻单位和一个统治者防守单位。
- 一条合法合成路线和一条失败合成测试路线。
- 一个节点局部地形修正。
- 一次普通攻击、一次真实伤害行为和一个状态效果。
- 一张在沙盘被拒绝、在玩家符合条件的行动回合被接受、在该回合之外被拒绝的基础非 A 卡；遭遇战测试还必须证明每个玩家行动回合最多一张。反应、打断或额外行动窗口是否额外给予卡牌使用额度，随精确遭遇战规则一并延期确认。
- 一个可以在沙盘中发动、无需进入战斗的 ABC 卡主动技能。
- 一次高光战争天平事件。
- 两个已经确定的 MVP 战役胜利条件都必须可测试：统治者核心生命归零，以及战争天平达到玩家胜利边界。局部战斗还必须提供一个已配置的失败结果，并恢复战前快照。

Encounter 与 ACT 的随机规则结果须在相同受控输入、定义版本、逻辑时点和种子下复现，并输出可读战斗日志；这不保证任意 ACT 物理过程重放。ACT 切片通过自己的模式专属效果解析器证明减速、保持惯性的子弹时间输入、五槽映射、卡牌分发和完整结果；基础技能身份／槽位仍共享。

## 12. 战斗验收清单

- [ ] 遭遇战存在由条件驱动的行动条，并明确先攻、优先级、反应、打断、额外行动和非回合窗口。
- [ ] 攻击伤害和真实伤害走不同结算路径。
- [ ] 至少一组 F/D/R 克制关系可见且可测试。
- [ ] 移动、放置、攻击和节点占领通过命令完成。
- [ ] 基础非 A 卡在战斗外和非玩家符合条件的遭遇战行动回合被拒绝；每个玩家行动回合最多接受一张。
- [ ] ABC 卡主动技能默认可以从沙盘发动，并接受其配置的特殊限制。
- [ ] ACT MVP 中点击 `Tab` 打开卡牌仓库、使背景虚化、划出五张卡，将世界时间降至 1/10，禁止移动和攻击输入，保持场景惯性，只接受基础非 A 卡输入，并能按数字键选择对应卡槽。
- [ ] `Tab` 打开共享卡牌仓库，Encounter 手牌与 ACT 卡槽一一对应。
- [ ] 战争天平从 50/50 开始，只通过配置事件移动。
- [ ] 一次统治者巡逻、增援和反攻可以复现。
- [ ] 潜行与发现对玩家可见。
- [ ] 合成失败不会隐式变成部分成功。
- [ ] 相同种子产生相同的战斗和 AI 结果。
- [ ] 失败或退出时完整战前快照可以恢复所有被战斗修改的本局状态，胜利时提交战斗结果。

## 13. 开放的战斗决定

- 遭遇战行动条优先级、先攻修正、响应/打断优先级、额外行动规则、非回合窗口、结束回合效果，以及这些窗口的精确出牌额度。该部分有意留空，等实现用到时再确认。
- ACT 第一轮完整战斗之外的后续内容细节。
- ACT MVP 的触发方式、背景虚化、禁止移动/攻击输入和时间倍率已确定为 `Tab` 与 1/10。持续/切换行为、冷却/资源消耗、页面边界行为和总页数仍待确认。
- ABC 主动技能是否也能在遭遇战或 RealTimeAction 战斗中发动。
- 形意、抗衡、归墟的最终语义和区别。
- 超出两个已确定 MVP 胜利条件的未来结局扩展，包括信仰崩塌和主题化成就；文档规定的失败方式也必须保持数据驱动和可扩展。
- 威慑力阈值、反攻规则和天使行为。

## 14. 学习目标

本基线用于学习 Gameplay Framework 边界、命令处理、战斗结算、状态效果、GAS 准备、AI 状态/效用策略、动画时机契约、物理交互、确定性调试，以及战略沙盘/遭遇战/RealTimeAction 输入抽象。

## 15. 独立模式体系与出战阵容（2026-09-08）

两种模式按 [ADR-0004](../../Decisions/ADR-0004-Separate-Encounter-and-ACT-GAS.zh-CN.md) 使用原生 GAS，拥有独立技能／效果配表、时钟、生命周期和模式运行状态。回合制角色卡部署于沙盒；ACT 使用独立角色卡集合和战斗总设置选择的角色／武器阵容。基础非 A 技能身份／槽位映射共享，模式效果不同。

地形／上下文可限制 ACT 卡的某特性。出战资格与特性限制由权威路径校验，包含绕过 UI 的直接命令；不会静默将特性限制变成角色排除。TASK-035／027／030 分别拥有阵容配置、上下文交接和执行。其余阵容／限制规则和未接受数值由 D20／D03 中的用户决策确定。单位死亡或技能打断应返回 Encounter 时间线，除非获准局部结果规则终止战斗。
