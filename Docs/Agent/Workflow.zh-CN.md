# Agent 工作流

先看要求和相关代码，做完改动，验证，再告诉你结果。默认一个主 Agent 负责，不固定走策划、执行、审查、教学接力。

- 小修复和解释不建 TASK。复杂、要跨会话继续的工作，才留简短任务说明。
- TASK 只写当前目标、重要决定、验收、最新证据和下一步。旧过程有用就归档，不不断往后追加。
- 只更新事实真的变了的文档。项目现状不当流水账，Changelog 不记每个小改动。
- 中文只用大白话讲重点，细节链接英文；新内部记录不用强制双语。
- 验证按风险做：改 C++ 要编译，改规则要测；存档、回滚、GAS 生命周期等重要改动，集成前做针对性独立审查，除非你选了别的验收方式。
- 编译过、自动测试过、实际试玩过、打包过要分开说。完成任务不等于可以合并或推送。

不清楚玩法或重要取舍才问你，普通技术选择直接推进。教学只在你需要时进行。

详细依据、操作和证据见[英文原文](Workflow.md)。
