## 打开与试玩

在桌面浏览器打开 [index.html](index.html)。HTML、CSS、JavaScript 完全离线运行，无需服务器或安装依赖。更新后刷新已打开的页面，顶栏应显示 **HTML 0.4**。保持这些文件在同一目录。保存／继续使用当前浏览器、当前入口的本地存储，换浏览器或入口位置可能读不到原存档。这是新的可玩原型，与旧可视化缓存里的草图不同。

用户已确认初版页面能打开并进入地图。浏览器自动化的安全策略拒绝访问本地文件 URL，未尝试替代访问。新交互与画面仍需手动浏览器验收；状态测试是另一类证据。

## 验证这次修改

1. 开始试玩。**单击归处**只查看；**双击归处**打开完整编队页，右侧“进入归处编队”按钮也能进入。这些操作都不移动卡牌、不扣资源。
2. 切换顶部 **节点细节／主角展示／其他模式**。节点细节读取真实的归处核心、坐镇主角与已部署 ABC 实例；“查看地块场景”仍打开独立的放置场景预览。
3. 在主角展示中，预览两名占位主角、三套服装、剑／长枪及兼容姿势，然后保存坐镇／展示配置。未保存就返回，只丢弃预览。换装不授予数值、ABC 卡或 ACT 装备。
4. 在其他模式中切换 ACT／FPS，选择并保存该模式角色／武器。下场 ACT 使用已保存的招募角色；FPS 仅验证选角，不开放战斗。修改任一模式不应改变主角或另一模式。顶栏全局配置读取同一份 ACT 状态。
5. 回沙盘进入晌午。部署 **佛罗伦萨的曙光**，附着 **山樱一梦**，勾选整组从归处移到 **薪火台**。推进黄昏 → 黎明 → 晌午，让场域累加一次。
6. 在薪火台预览并执行合成。A／B 进入 ABC 弃牌堆；成功的 C **直接在薪火台登场**，只触发一次登场，不进手牌、不再收部署费。新 C 会自动选中，可继续移动；失败不产生任何卡牌。
7. 到达 **守望人驿站**或 **熔炉**后点对应操作。阅读台词、推进和查看分支。打开、推进或取消都不领取；最终接受选项才结算原有一次性效果，完成后不能再领。Escape 和“暂时离开”均取消且不消耗事件。
8. 在沙盘保存、刷新并继续。主角外观、ACT／FPS 编队、地图上的 C、已完成事件都保留。战斗／剧情必须结束或取消后才能保存、读档。

## 第一轮战斗

默认路线：归处 → 薪火台 → 风蚀原 → 旧日熔炉 → 王庭归处。合成 C 可直接移动；开局手中的舞女仍可从手牌部署。目标有敌人时，在独立“移动到此处”命令处选择 ACT 或 Encounter。

- ACT：WASD／方向键或点击场地移动；空格／普攻按钮攻击范围内敌人。Tab 打开五槽技能库，世界降为 1/10 速度，1–5 用牌；面板内拒绝移动／普攻输入，已有惯性继续。再次 Tab 关闭。
- Encounter：按行动条的下一就绪时间行动。每次我方行动可先用一张基础技能，再普攻或防御。普攻先点按钮，再点存活敌人立即执行。舞女可在攻击控件里选择两个目标；点到第二个不同的有效敌人后执行。
- 基础技能进独立弃牌堆，耗尽后洗回；ABC 原料使用另一套弃牌堆。
- 局部失败／退出完整恢复入战前状态，包括移动费、卡库、随机流、阵容和日志；胜利提交。此试玩配置可通过核心归零或天平抵达玩家边界取胜。

## 选目标、手牌与单位详情（0.4）

1. **长按约 500 毫秒**查看任意我方或敌方单位。详情展示立绘占位、当前所有可用数值与技能；等级明确显示为**未配置**，不从其他数值猜测。查看详情不攻击、不扣费。
2. 先点**普通攻击**进入选目标状态，点**取消**可免费退出。默认选择一个目标，点击有效敌人便立即攻击该敌人。舞女可以在攻击控件中把目标数改为两个：第一次点击选择一个敌人，第二次点击另一个有效敌人便对两者执行攻击。卡面上限为两个，不会自动补选其他目标。
3. 从底部手牌向上拖基础技能。单体牌放到对应的存活非核心单位上，**鱼骸骤雨**放到战场内。有效松手只打开目标／费用预览，点击**确认释放**才扣费并结算。拖放、选中和预览本身不消耗资源；**取消、Escape、无效拖放**均免费。
4. 也可以点击卡牌或按对应数字选牌，再点击有效单位／战场并确认。更换卡牌／目标会更新预览。每个我方行动仍只允许一张基础技能，用牌后仍可执行该单位的普攻或防御。
5. 基础技能来自**卡牌或环境**，没有 C 卡施法者，也不从角色拉出攻击轨迹。鱼骸骤雨从天而降，分三波砸中**敌我双方**。普通攻击保留角色到目标的动作表现。

这些页面交互由用户试玩验证。本次未实现 UE 功能；后续 UE 的卡牌动画、Sequencer 与材质／Shader 表现仍待制作。

## 0.3.1 动作卡住修复

修复“动作播放中”永久禁用操作：默认浏览器计时器改为通过全局宿主调用；启动调度、绘制或结束回调异常时取消剩余动画，从已经结算的游戏状态重建界面，不重试攻击、不重复扣费。控制台保留错误，界面给出恢复提示。

重新测试前，若要保留旧页面中的本局，先在顶部“退出并回滚”，在沙盘保存，再 Ctrl+F5 刷新至当前 **HTML 0.4**，继续存档。分别用基础技能、普攻、防御检查是否结束播放并开放后续行动。维特鲁威人／舞女双角色组合已在 0.3.1 加入回归测试。

此前 85 项测试用替代计时器绕过了真实默认调用路径，不能证明浏览器正常。新版输入测试加载实际浏览器全局模块及默认 Playback，通过校验调用接收对象的计时器替身覆盖此缺口；仍未把 Node 替身当作真实浏览器验收。

## Encounter 动态反馈试玩路径

快速入口：开始试玩 → 推进到晌午 → 部署手牌“希律的舞女”到归处 → 勾选移动 → 薪火台 → 风蚀原 → 点击关隘，右侧选择 **Encounter**，再“移动到此处”。每移动一次，重新勾选该卡再去下一节点。

1. 看顶部“轮到你了／敌方即将行动”，对应单位带有文字与边框高亮。行动条预测后续六次行动，同一个敌人可再次出现，不是双方固定交替。
2. 使用舞女，在攻击控件中选择两个目标并点普通攻击，再依次点两个守卫：点中第二个后执行。分别显示舞女到所选目标的轨迹，命中时震动、浮字、血条变化。播放过程中不能重复出牌；1×／2× 只调整表现速度。后续行动保留默认单目标，检查首次点中有效敌人是否立即攻击。
3. 我方行动时把“风”或“咒”拖到友军身上，确认后观察归墟／抗衡增加，再普攻或防御。受击时显示吸收／抵挡；“一刀两断”标注真伤，“光”按实际恢复量显示，“雨”从天而降，分三波覆盖双方。另取消一次预览，确认不消耗资源。
4. 留意最终一击：倒下与胜负提示播放完才切回地图。普通播放中仍可“退出并回滚”；结算展示期间暂时锁住退出和全局菜单。
5. 在敌方准备行动时误按数字技能键，拒绝操作后敌方仍应正常行动。播放中离开页面再通过浏览器后退返回，应恢复可操作的权威状态，避免停在旧的禁用画面。
6. 缩放窗口检查双方单位与轨迹；系统开启“减少动态效果”时，应保留文字、静态连线、血量反馈，去掉移动粒子和震动。

技术边界：使用本地 SVG/CSS，不需要 Three.js 或联网下载。引擎只输出临时结构化回执；独立播放层读取结算前后副本，不改数值、行动顺序或存档。原有 ACT 操作保持。“雨”击倒当前行动所属单位、队友仍存活时，按现有存活单位行动条推进。0.3.1 基线记录了 92 项 Node 测试通过（47 原有 + 20 回执 + 25 播放／输入／绘制替身）；这项历史结果不证明新 0.4 交互或真实浏览器视觉效果，以上步骤仍待人工验收。

## 数据与限制

`data.js` 保存带来源的卡牌定义、可修改 HTML 临时参数、地图、独立外观／招募名册和原创占位对话；`engine.js` 负责状态及命令校验；`app.js` 接输入；`card-input.js` 维护基础卡选目标与确认预览；`home-ui.js` 组合外观层；`style.css`／`home.css` 负责表现；`encounter-fx.js`／`encounter-fx.css` 播放 Encounter 动作与命中。插画是 SVG 占位，不是导入模型或动画资产。

卡面明确数值与 HTML 临时参数分开。参数页在新开局时生效。所选九张 ABC 仅实现卡牌“已接入”说明中的效果，其余技能没有冒充完成。信仰公式在 80 处的原文跳变照录，没有擅自平滑。

仍未接入：其余 PDF 卡牌／技能、B 直接使用／多 B 合成、完整 ABC 耗尽／债务规则、全部时代／状态优先级、统治者巡逻／威胁／增援、好感 Buff、更多整局失败、正式路由、真实 GAS／UE 运行和正式美术。极端自定义参数可能使一局难以推进；默认参数是可复现样例。当前主角／编队选择属于本局，永久养成以后再定。

旧版 v1 存档仅补充缺失的新主角／FPS 字段；已有但无效的身份会拒绝加载。不会猜测并搬迁旧存档里已生成的卡；验证新合成流程时请开一局 0.4。

## UE 承接建议——本次未实施

建议 **CommonUI 管页面与输入栈，再配一个可复用的 3D 展示舞台**。两者职责不同。归处三个栏目在页面内部切换，不必每个栏目都 OpenLevel。CommonUI 提供可激活 UI 与输入路由，参见 [Epic CommonUI 概述](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-advanced-multiplatform-user-interfaces-with-common-ui-for-unreal-engine)。

展示舞台可以单独保存为小型 `.umap`，按需加载／流送。首版优先主视口展示相机，上面覆盖 UI，返回后恢复沙盘镜头／选择；隔离展示灯光、碰撞和输入。只有需要 UI 内嵌小窗或同时多个视角时再用 SceneCapture2D／Render Target，承担额外渲染和显存成本；隐藏时停止捕获，不能每帧自动捕获又手动重复捕获。参见 [关卡流送](https://dev.epicgames.com/documentation/unreal-engine/level-streaming-overview-in-unreal-engine?lang=en-US)、[CaptureScene](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/USceneCaptureComponent2D/CaptureScene)。

归处以后若成为可自由走动、拥有自身玩法及大量 NPC 的基地，或需要卸载沙盘节省内存，再考虑独立完整关卡；其中的编队菜单仍可用 CommonUI。

主角、ACT 手下、FPS 手下和 ABC 实例各用独立 ID。选择解析到对应定义，以及模型、服装、武器外观、兼容姿势的软引用；展示 Actor 是临时对象，存档只记 ID。不要把 ACT 技能表复制到通用外观资产。切角后，旧的异步加载结果不得覆盖新选择。更换展示武器不自动更改招募角色的战斗装备。

剧情使用静态 StoryId／台词节点／说话人／文本／选择／条件／后继／效果定义，附可选语音、立绘和序列软引用。剧情服务校验选择命令，再调用世界／资源服务；用完成记录和效果 ID 去重。UI 只呈现状态。存档记录带版本的进度、选择和完成事实，不存 Widget 或 Actor，先支持剧情前后安全存档。LevelSequence 负责镜头／人物演出，不单独拥有分支与奖励真值；跳过、重播、倒放均不能重复领奖。参见 [Epic Sequencer 事件轨道](https://dev.epicgames.com/documentation/unreal-engine/cinematic-event-track-in-unreal-engine)。

用户要求后续 Encounter 用 Sequencer 表现手牌动作，并加入材质／Shader 效果。基础卡的表现绑定卡牌／环境及所选目标，“雨”绑定天空／战场，而不是 C 角色。玩法命令继续负责校验、费用和一次性结算，动画播放、跳过或重播均不能再次应用卡牌。

这些是后续架构评审／ADR 的需求与建议。本任务未开启 UE 插件、未改地图／引擎依赖，也没有写 C++。

## 验证

安装有 Node.js 时，在仓库根目录执行：

```powershell
node --test Prototypes/HTML/engine.test.cjs Prototypes/HTML/encounter-events.test.cjs Prototypes/HTML/encounter-fx.test.cjs Prototypes/HTML/card-input.test.cjs
node --check Prototypes/HTML/app.js
node --check Prototypes/HTML/home-ui.js
node --check Prototypes/HTML/encounter-fx.js
node --check Prototypes/HTML/card-input.js
```

引擎用例覆盖每日时机、带种子合成、整组移动、剧情完成／取消／回滚、身份隔离、存档迁移及两种战斗。自动状态检查不证明浏览器双击、长按、拖放、布局、键盘手感或实际 UE 行为；试玩时记录上面的修改验证步骤与 0.4 新交互结果。
