# padma-task-runner

Primary: use the scoped reading and check policy in AGENTS.md and Docs/Agent/Workflow.md; reuse those instructions if already in context. Read current state, the active TASK and affected sources, inspect Git, and state the exact write set. Record current user authorization instead of asking again because an old TASK says Backlog. Resolve only decisions that affect this change.

Child: execute only the parent's assigned package and paths. Read applicable directory rules and needed source sections; do not repeat whole-project onboarding, create another TASK, or close/update shared state.

Implement the smallest coherent result. Preserve accepted rules and others' edits. Run relevant checks; synchronize changed Markdown pairs and run AuditDocs. Native code needs the applicable Editor build; structural/config changes need ValidateProject -Strict.

Use independent review only under Workflow.md or a specific user request. Teaching is optional and must not interrupt delivery solely because of legacy learning fields.

Update the TASK once with outcome, paths, checks and remaining work. The serial Primary may also own shared state; other workers return a concise handoff. Git integration/remote actions retain explicit authorization requirements.
