# Padma 任务执行 Skill

- 英文原文（Agent 读取）：`SKILL.md`

这个 Skill 用一份任务契约作为一次交付单位。可变化的项目事实仍保存在 `Docs/` 中；这里仅保存可重复执行的流程。

## 1. 建立契约

1. 阅读 `AGENTS.md`、`Docs/00_INDEX.md`、`Docs/ProjectState.md` 和当前英文 `TASK-xxx` 文件。
2. 阅读任务点名的英文规则、架构、模块和决策文档。
3. 确认一个可观察 Goal、一个 Primary Agent、允许路径、非目标、依赖、验收标准、验证方式以及一至两个学习目标。
4. 检查 Git 状态并报告无关或重叠修改，不得静默删除或吸收。
5. 不实现 `Backlog` 状态的任务。只有任务为 `Ready` 或 `In Progress`，且必要的用户决定已经记录后才能推进。

## 2. 选择执行形态

- 如果工作只有一个验收边界和一个完整写入集合，就保留在当前 Goal。
- 如果结果能独立审查和合并、需要多个回合、且有独立写入集合，则请求父 Agent 建立独立 Goal/worktree。
- 只把边界明确的工作包交给 subagent，并附上 Role、问题或任务切片、输入、预期输出、约束和读写权限。
- 探索、策划、架构审查、测试设计和 Review 优先使用只读 subagent。
- 禁止两个写入者同时修改同一文件、UE 资源、地图、公共模式或中心配置。

## 3. 执行并学习

1. 修改前说明目标路径。
2. 做满足契约的最小完整修改。
3. 保持已验收规则和明确延期内容；代码、数据和文档冲突时停止。
4. 每一对发生变化的中英文 Markdown 必须同步。
5. 落实任务的学习目标：解释概念、让学习者预测、安排一次小型亲手检查并记录证据。

## 4. 验证与交接

1. 运行最窄范围的测试或可复现手工检查。
2. Markdown 变化后运行 `Scripts/AuditDocs.ps1`。
3. 仓库结构或共享配置变化时运行 `Scripts/ValidateProject.ps1 -Strict`。
4. 按允许路径和验收标准检查 diff。
5. 更新任务完成报告；只有集成负责人更新共享里程碑状态。
6. 报告修改文件、检查、证据、剩余风险、未决问题和学习证据。

除非用户明确授权，不得合并、强制推送、创建发布标签或推送远端。
