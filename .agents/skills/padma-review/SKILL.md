# padma-review

Read the assigned TASK acceptance, actual diff and relevant source sections under applicable AGENTS. Expand only along an affected dependency; do not load every referenced design document.

Check concrete behavior, accepted rules and applicable ownership/determinism/save/lifecycle risks. Use existing valid check evidence; run a targeted check when it resolves uncertainty. After fixes, recheck the fix and affected boundaries, not the entire repository again.

Return actionable findings first: P0 data loss/unusable build; P1 acceptance or major rule/contract failure; P2 significant edge/regression risk; P3 optional improvement. Each finding needs a path, impact and verification/remedy. Avoid style-only findings.

Finish with Block / Conditional pass / Pass, checks and unverified risk. Distinguish user playtest pending from code defects. Stay read-only; no merge/push or approval based solely on a worker narrative.
