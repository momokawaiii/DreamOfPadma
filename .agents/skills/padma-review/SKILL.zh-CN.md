# Padma Review Skill

- 英文原文（Agent 读取）：`SKILL.md`

Review 必须独立于执行者的叙述，以任务契约和英文规范文档作为证据来源。

## Review 流程

1. 阅读 `AGENTS.md`、`Docs/00_INDEX.md`、`Docs/ProjectState.md`、当前任务以及任务点名的所有规范文档。
2. 检查真实 diff 和仓库状态，不能假设执行者声称的检查或文件清单完整。
3. 只审查分配的修改；但相邻问题若会直接破坏验收或集成安全，应一并报告。
4. 按需检查以下通道：
   - 任务范围和验收标准；
   - 是否忠于已验收规则、是否保留延期决定；
   - 所有权、依赖方向、数据驱动边界和 ADR 需求；
   - 确定性、存档迁移、未来网络权威和回滚；
   - 运行错误、回归、边界情况、测试质量和缺失证据；
   - UE 资源/地图所有权和生成文件卫生；
   - 中英文 Markdown 含义同步。
5. 有条件时运行安全的只读检查或测试，并明确未验证内容。

## 问题报告格式

问题在前，按严重程度排序：

- `P0`：数据丢失、仓库破坏、安全问题或构建不可用。
- `P1`：验收失败、规则被破坏、重大回归或不安全的公共契约。
- `P2`：重要边界情况、可维护性风险或可能掩盖缺陷的缺失测试。
- `P3`：不阻塞验收的有限改进。

每个问题写明违反的契约、确切文件或章节、影响和具体验证/修复方向，不做纯风格评论。

结尾写明：

- 验收状态：`Block`、`Conditional pass` 或 `Pass`；
- 已运行和未运行的检查；
- 剩余风险；
- 必须补充的双语文档或任务状态更新。

除非用户明确要求另建修复任务，否则保持只读。Review 阶段不得合并或推送。
